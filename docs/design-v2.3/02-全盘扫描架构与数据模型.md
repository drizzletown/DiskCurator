# 双扫描范围：总体设计

## 共享核心与边界

```text
Win32 扫描范围选择器
 ├─ 全盘扫描（默认） → Windows GetLogicalDriveStringsW + GetDriveTypeW + GetVolumeInformationW
 │                    → scan_roots_hashed({C:\, D:\, E:\, ...})
 │                    → FullScan {volumes[], errors[], hash_candidates[]}
 │                    → 只读全盘概览 → 人工选卷 → 单根管理/执行
 └─ 指定目录扫描   → 用户目录选择 → scan_hashed(root)
                                         → 单根目录分析与受控操作
```

## 数据结构

`dc::FullScan`：含 `volumes : vector<Inventory>`（各卷独立根路径、目录、文件、SHA-256）；`errors` 保存访问失败的卷及其他扫描阶段异常；`total_files` 与 `total_bytes` 是**成功枚举**的数量和大小；`hash_candidates` 是 `(size, SHA-256) → 多个 (volumeIndex, fileIndex)`。

**不声明**两个哈希相同的文件已经字节一致。`FullScan` 没有“跨卷清退”API。进入单卷后通过 `dc::deduplicate` 的逐字节确认建立原有内容等价关系，然后才能生成文件操作计划。

## 资源与性能

- 扫描包含系统盘时，`%LOCALAPPDATA%\DiskCurator\Cache` 有可能位于扫描卷内部。扫描引擎明确跳过此应用缓存目录，允许安全保存索引并避免缓存重复收录自身。绝不扫描链接目标。
- 所有卷顺序扫描，降低多移动硬盘同时随机 I/O 的风险；随时检查取消信号。
- 大量文件仍会保留各卷的内存 `Inventory`。单卷选择后释放其余卷清单；数百万文件内存优化、设备并发控制和跨次增量索引仍是后续性能任务。
- 不能静默跳过卷：未就绪/无权限/被断开的卷或文件，必须在报告中列出；`complete()` 为 false 时不能给出完整性声明。

## Windows 接口职责

- UI 下拉框 `ID_SCAN_SCOPE=230`。0=全盘（默认）、1=手工目录。
- `Task::ScanAll` 只读生成 `FullScan`；`Task::FocusVolume` 复用单卷清单并执行精确内容验证；`Task::Scan` 保留原单目录流程。
- 确认属于某个卷后，后续操作计划使用该卷的原有根路径和安全执行器。任何跨卷操作仍不支持。
- GUI 冒烟测试只能在临时夹具运行：先验证默认全盘选择，再切到手工目录，不能自动触发读取真实 C 盘。
