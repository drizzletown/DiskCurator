# 04. 验证矩阵与实现差距（rc11）

## 本次实际完成的编码工作

- Win32“选择磁盘扫描”模式：明确勾选卷、冻结 GUID/序列号/类型、扫描前后校验；未选中卷不进入扫描任务。
- Win32“指定目录扫描”继续保留；默认全量 SHA-256，开始前需要人工触发。
- `Observations` 只读派生模型：跨已选范围的文件同哈希候选计数、含空目录的相同目录树指纹候选数，不二次读取文件。
- 扫描结果的可切换观察视角；文件/目录列表显示容量、副本候选数、路径与哈希状态；哈希副本组显示所有展开的候选成员（有显示上限）。
- 单根精确核验之后，可从当前行的右键菜单进入人工隔离、双目录比较、融合预览、映射编辑、计划执行及查看位置；执行器与用户保留策略未改动。
- Windows GUI 自动测试脚本新增真实观察切换、候选计数搜索和结果集恢复的检查；测试只用临时文件夹，不尝试扫描用户真实磁盘。

## 正式版发布阻断项

1. 用 Visual Studio 2022 + Windows SDK 编译整包，运行 CTest、GUI 和 CLI 烟雾脚本；验证中文路径。
2. 实盘勾选 E:、F: 后抓取 I/O 证据，确认 C: 未被枚举任何内容；拔掉 E: 或让盘符重新绑定其它卷时必须拒绝复用旧结果。
3. 扫描 10 万小文件和大型媒体目录，记录磁盘读取量、取消延迟、峰值内存及筛选响应；相同哈希统计不得替代最终逐字节确认。
4. 对文件多选、目录双选、计划预览、隔离/撤销、结构映射逐一人工验收；必须确认路径/结果与选中项一致。

**结论：rc11 属于新扫描选择器和观察层已编码、核心可移植测试通过、Windows 原生体验未验收的源码候选。**
