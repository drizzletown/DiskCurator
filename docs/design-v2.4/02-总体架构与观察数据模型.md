# 02. 总体架构与观察数据模型

## 体系结构

```text
Win32 原生界面
 ├─ 扫描范围选择器：选定卷身份 / 指定根目录
 ├─ 观察视角选择器：文件 / 目录 / 哈希副本组 / 关系 / 风险 / 映射
 ├─ 上下文操作菜单：跟随选中记录，不堆叠全局按钮
 └─ 智能整理 / 主题任务 / 基础工具三层入口
          │
  应用协调器、任务调度、冻结输入、进度和取消
          │
  扫描器 scan_hashed / scan_roots_hashed
          │
  FullScan：每卷 Inventory + SHA256 候选组 + 异常
          │
  Observations（只读派生，无再次读取文件）
    ├─ FileObservation：所属卷、文件索引、同哈希成员计数
    └─ FolderObservation：所属卷、目录索引、目录树指纹候选计数
          │
  聚合观察 → 用户选择 → 单根精确验证 → 计划
          │
  文件/目录事务执行器（跨卷只读视图不提供删除/融合操作）
```

## 指标定义

1. **文件哈希候选副本数**：在本次选定扫描范围内，文件大小与完整 SHA-256 都一致的路径出现次数，包含自身。若哈希不可用，显示未知，而不是 0 份或 1 份。
2. **已验证文件副本数**：进入单根目录后，现有 `deduplicate` 的逐字节验证所归属的内容组大小。只有这个层级才能作为精确去重的内容依据。
3. **累计目录大小和文件数**：从扫描索引汇总全部后代普通文件，不包含软件尚未处理的特殊文件；权限不足时必须显式标记不完整。
4. **相同目录树指纹候选数**：对目录中的直接文件名、大小、文件 SHA-256、直接子目录名称及子目录树指纹递归聚合；空目录也参与。仅当整棵子树所有文件都有 SHA-256 时才能计算。外层目录名可以不同；此值**不代表字节证明的完全相同目录数**。
5. **潜在冗余容量**：在哈希候选组中 `(成员数-1)×单文件大小`，仅是上界型估计，不能当作真实可释放容量；受配置的保留份数、隔离/空间机制影响。
6. **目录重合/相似度**：`evaluate_directory_pair` 返回的内容多重集重合、Jaccard、较小侧覆盖率和同路径冲突；不是图像感知相似度，也不是自动融合命令。

## 技术约束

- `observations.cpp` 从 `FullScan` 计算派生指标；只做内存运算，不触碰硬盘。哈希候选不会进入可执行的删除/隔离计划。
- Windows 卷元数据在扫描前后进行身份比对。只将用户明确勾选的磁盘放入 `scan_roots_hashed`。
- 全量 SHA-256 目前每次读取全部可读文件；缓存索引持久落盘但**未支持增量跳过内容读取**。
- 观察视角的列表用 Win32 虚拟 ListView 呈现。大范围文件/目录视角最多展示容量最大的 5000 条；筛选时在完整扫描内存索引上重新筛选，而不是只搜索此前展示的 5000 行。必须显式提示截取。
- 已有单根目录执行器只能在选定的根目录范围内提交。选卷后复用整卷 Inventory 进入精确校验；跨卷字节验证、跨卷修改与事务恢复需要独立安全设计，当前未开放。
- UI 主线程执行观察筛选/排序时仍可能在百万级索引上出现卡顿；需后续对索引做后台筛选和分页。不能宣称已完成百万文件性能验收。
