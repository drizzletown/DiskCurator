# 02 — 扫描结果工作区与交互设计

> 1.0.2 交付补充：G-01/G-02/G-04 已补齐；缓存状态新增独立字段，CSV 带范围和状态。本文关于 1.0.1 的现状审计保留作对照，最新实现与验证以 [交付记录](../../RELEASE-ACCEPTANCE.md) 为准。

版本：设计基线 v2.6。日期：2026-11-20。实现核对对象：DiskCurator Native v1.0.1。

本章规定用户如何选择范围、观察结果和发起操作。**基础操作、主题操作、智能操作是同一结果工作区中的操作类别；不再设置左侧三种模式，也不设置独立的目录浏览树。** 本章中的“可视化”首先指有明确对象、指标、筛选、排序、选择和状态的结果表格，不代表已经实现容量矩形图、关系网络图或其他高级图表。

状态用语统一如下：“设计要求”是应满足的行为；“1.0.1 已实现”表示源码中已有相应路径；“待实机验收”表示仍需在 Windows 上观察运行效果；“后续能力”表示当前没有实现。源码审查和交叉编译不能替代 GUI 实机验收。

## 1. 工作区信息层次〔UI-01〕

### 设计要求

主窗口围绕正在查看的扫描结果组织，纵向分为以下区域。用户在任一观察视角上发起操作，进入参数或预览时保持可追溯的来源范围。

| 区域 | 必须可见的内容 | 交互约束 |
|---|---|---|
| 范围区 | 扫描范围模式、所选磁盘或目录、选择范围、开始、停止 | 开始扫描前明确本次范围；不默认勾选磁盘 |
| 进度区 | 阶段、进度条、工作量、速度、时间、当前路径与异常 | 任务期间持续可见；状态文字不能覆盖掉全部进度信息 |
| 观察区入口 | 当前视角、搜索输入 | 切换视角只改变观察投影；不自动重扫或运行主题分析 |
| 操作区 | 基础、主题、智能菜单；预览、执行和历史入口 | 菜单名表示操作分类，不改变工作模式 |
| 选择上下文 | 已选数量、所选行容量、当前操作根范围、结果是否过期 | 不用列表行号代替对象身份；目录嵌套时容量可能重复累计，不能当作净回收量 |
| 结果区 | 对象、位置或关系、容量或数量、证据与状态 | 占用窗口主要空间；说明行不能被误认为文件对象 |
| 状态区 | 显示范围、库存总量、候选组数、截取及异常提示 | 区分“当前显示的行”和“完整库存” |

### 1.0.1 已实现与验收边界

`init_controls()`、`layout()`、`paint()` 已采用全宽布局；没有创建旧侧栏模式控件、目录 TreeView 或旧选项卡。结果使用原生虚拟 ListView，视角使用下拉选择器。菜单与右键子菜单共用命令分发。

当前默认窗口尺寸为 1460×850，最小跟踪尺寸为 1060×670，布局按窗口尺寸调整结果区宽高；这两个数值是实现常数，不构成高 DPI 适配已经通过的证明。Windows 实机验收需覆盖最小窗口、最大化、中文长路径、100%／125%／150%／200% 缩放、菜单和对话框可达性。键盘完整操作与屏幕阅读器语义也未完成专门验收。

## 2. 范围输入与多盘结果〔UI-02〕

### 设计要求

默认模式名称为“选择磁盘扫描”。用户显式勾选 C:、D:、F: 等本次需要扫描的磁盘后，点击开始；默认不勾选任何磁盘。“指定目录扫描”用于一个目录及其子目录。不要在界面或说明中用“默认全盘扫描”表达“自动扫描所有可见磁盘”。

磁盘项应显示可识别的盘符、卷信息和容量。范围确认后记录卷身份；磁盘断开或盘符对应卷改变时，拒绝旧库存继续驱动文件操作。改变扫描范围或重新扫描会使尚未执行的计划失效；若存在待执行预览，应明确说明将放弃该预览。

多盘结果允许共同观察。进入某一盘进行操作时复用该盘现有库存，不再次读取文件内容；当前写操作限定在一个根范围内。混选不同磁盘的对象时，说明当前操作需要同一根范围，不能静默只处理其中一盘。返回全部结果不得清除“结果已过期”状态。

### 1.0.1 已实现

`switch_scan_scope()`、`choose_drives()`、`run_scan()`、`same_drive()` 实现上述范围入口与卷身份检查。`focus_volume()`、`ensure_result_scope()`、`return_to_all_results()` 在多盘与单盘观察间转移现有库存。选择磁盘对话框会保留仍符合卷身份的已有选择，但首次启动不预选磁盘。

## 3. 观察视角与证据表达〔UI-03〕

### 设计要求

每个视角回答一个明确问题；显示的副本数必须能够解释“计数范围、是否包含自身、证据级别”。没有读取完成的对象应显示未知或未完成，不能把它显示成“0 份副本”。目录内容不完整时不能给出完全相同的结论。

| 观察视角 | 用户要回答的问题 | 结果的核心内容 |
|---|---|---|
| 扫描概览／扫描问题 | 扫了哪里，哪些内容没有完成？ | 根范围、文件数量、容量、完成状态、读取问题 |
| 文件 | 这个文件在哪里，有多少相同内容候选？ | 名称、路径、大小、哈希摘要、候选或精确副本数 |
| 目录 | 哪些目录占空间，是否存在相同目录树？ | 路径、累计文件容量、文件数、目录树候选数及完整性 |
| 文件副本／目录副本 | 同一组成员有哪些，可以人工管理哪些？ | 分组、成员位置、容量、候选或精确证据 |
| 目录关系／双目录评估 | 两个目录共有、独有和冲突的内容是什么？ | 内容交集、覆盖率、同路径一致与冲突、两侧独有、目录包含关系 |
| 副本保障 | 哪些内容只有一份候选，哪些内容未读完？ | 当前策略、计数范围、单份或未完成文件 |
| 相似照片 | 哪些图片值得人工比较？ | 感知相似候选、距离、元数据、解码错误；不作为内容相同证明 |
| 融合建议／目录重组映射 | 可以怎样补齐或重组，依据是什么？ | 建议方向、证据、原路径到目标路径、冲突与解释 |
| 操作预览／历史 | 将修改什么，已经发生了什么？ | 计划源目标、策略、复制或移动类型、事务状态 |

### 1.0.1 已实现与当前差距

多盘概览提供扫描概览、文件、目录、哈希副本组和扫描问题；进入单根后提供上述分析、计划与历史视角。未运行照片、关系或智能分析时，视角显示入口说明，不把“尚未分析”当成“没有结果”。首次扫描不会自动执行这些分析。

文件及目录的候选数包含自身。文件列表显示 SHA-256 的前 12 个字符作为摘要，完整 SHA-256 仍参与搜索。候选标签为“同哈希候选／同树哈希候选”；完成相应字节核验后才使用“精确副本／精确相同目录”。

**计数范围仍需进一步统一呈现：** 多盘观察中的候选数按本次全部扫描根统计；进入单盘后文件、目录观察仍沿用这些候选计数，而单根精确核验后的计数限定于该根。当前行标签没有在每一处同时写明这个范围差异。设计要求是在计数旁明确标注“本次扫描范围候选数”或“当前根已核验副本数”，不能把跨盘候选数量解释为当前操作可用的保留者数量。该呈现要求尚未完整落实。

少量未分析或空结果提示仍沿用旧按钮名称，如“比较目录”“照片相似”；实际入口已在操作菜单中。本基线统一使用新的菜单路径，旧提示文案列入后续一致性清理。

## 4. 从结果发起操作〔UI-04〕

### 设计要求

操作的完整上下文由“扫描会话与根范围、对象身份、操作参数、策略、预览版本”共同确定。菜单可用状态用于帮助选择；执行前仍必须校验真实范围和计划条件，不能仅凭按钮可点击就认定对象可操作。

| 类别 | 入口及默认作用范围 | 范围说明 |
|---|---|---|
| 基础操作 | 查看位置、隔离所选文件、重命名、双目录评估、选择／清除、导出、策略配置、撤销 | 隔离使用明确选中的文件；撤销是事务操作，不是任意历史行的直接反向删除 |
| 主题操作 | 两目录融合、所选目录清退、当前范围的重复副本整理、归档、照片、精确核验、目录关系 | 明确区分“所选对象”“A/B 子树”和“当前扫描范围” |
| 智能操作 | 当前范围融合建议、目录重组映射、映射编辑、重组预览、拒绝建议 | 建议只产生解释和方案；用户确认执行前不修改资料 |

打开任一操作菜单不清空当前观察结果，也不启动扫描。作用于全根范围的任务必须在菜单与参数对话框中写明“当前范围”，不能因为用户只选择了一行，就让用户误以为任务只涉及该行。

### 1.0.1 已实现与能力边界

`action_menu()` 与 `run_action()` 共用顶部菜单、右键菜单的命令路径。全范围关系、融合建议和结构建议在明确发起后，可能先执行当前范围的精确核验；这部分读取不能算作初次扫描。所选文件隔离、策略隔离、目录清退可直接从哈希候选生成预览，不会先强制核验全根所有重复组。

当前“重命名”接受一个文件，或一个目录内的规则批量命名；尚不是对任意多选文件集直接应用统一批量改名。当前删除类动作是可撤销隔离，不提供永久删除，隔离本身不释放磁盘空间。目录融合保留源文件与冲突版本；普通撤销不等于删除所有融合产物。

## 5. 选择、搜索、排序与导出〔UI-05〕

### 设计要求

文件或目录的选择以所属扫描根和相对路径为对象身份。列表行号只是临时显示位置，不能跨筛选、排序、刷新或后台任务复用为文件目标。关系行、建议行与映射行应携带自己的关系或计划身份，不把说明行当成普通文件。

| 触发事件 | 必须执行的选择规则 |
|---|---|
| 点击列头排序 | 对仍存在的同一对象保留选择，不按旧行号保留 |
| 搜索输入改变 | 立即清除旧选择，再更新结果；不能在延迟筛选期间执行旧选择 |
| 切换观察视角 | 清除不再对应当前对象类型的选择；当前实现同时清除该视角搜索 |
| 启动后台任务 | 冻结本次对象和参数；在任务期间禁止改变驱动该任务的选择 |
| 结果刷新或返回单根 | 只恢复能够按同一根范围和对象路径重新识别的选择 |

### 1.0.1 已实现

虚拟列表通过显示索引映射到结果行；排序和重建使用包含路径及来源信息的行键恢复选择，跨分析任务使用相对路径集合恢复选择。当前行键还包含展示文字，并不是独立持久对象 ID，因此标签变化时允许选择被清除；其必要约束是不能把选择转移给另一个对象。

搜索采用约 180 ms 合并刷新。输入变化时先清选择，发起操作前先完成尚未处理的筛选。文件和目录视角先对完整库存匹配，再截取展示；文件搜索支持路径、完整哈希、容量和副本标签，具体可搜索字段随视角而定，不能把它理解为通用结构化查询语言。

常用文件、目录、文件副本、目录副本及副本保障视角限制一次构造的展示行数，当前上限为 5000；文件／目录大列表截取容量较大的匹配项，并显示截取说明。用户应能用更具体的搜索找到未直接展示的对象。**该上限并非所有视角的统一分页实现**；照片明细和部分计划明细仍有独立的规模与呈现约束。

“选择全部”明确表示选择当前显示行。“导出”明确表示导出当前显示结果 CSV，不声称导出了所有匹配对象或全部库存。CSV 保留当前展示内容，过期快照会附加过期说明；完整库存分页、全量导出和独立哈希详情面板是后续能力。

## 6. 双目录评估与融合〔UI-06〕

从目录或目录副本视角选两项，可将其填入 A/B 参数；也可以手工输入当前根内的两个相对路径。目录关系视角选中的关系可提供一对默认路径。用户在对话框确认左右方向，评估与融合不得把显示排序当作隐含的“新旧版本”判断。

评估结果展示共有内容、两侧独有、同相对路径一致和冲突、结构与空目录信息、包含关系、相似性指标；分母为零时显示“无定义”，不伪造 100%。A/B 分析复用扫描库存，并只在两个子树的并集内进行内容确认；与 A/B 无关的文件不参与本次内容读取。

根目录与子目录、父子目录可以作为只读评估对象；直接融合要求两个适合融合且不相交的子树。评估完成后可以询问是否生成左到右的融合预览，该询问不执行文件写入。预览必须显示来源、目标、待复制、新建目录、已有相同文件和冲突处理，并明确原文件保留。

1.0.1 对应 `do_pair_assess()`、`present_pair_report()`、`do_merge()` 和范围分析 API。跨根或跨磁盘 A/B 融合不在当前能力内；两盘中的目录可以共同观察，但不能通过界面混选绕过写入范围约束。

## 7. 预览、执行与历史〔UI-07〕

新操作先收集参数，再后台生成可检查的预览。正式开始生成新预览前，清除旧的待执行计划；新预览失败、为空或被取消时，不能继续执行之前的旧计划。修改目录或逐文件映射也使原预览失效，重新生成后才能执行。

预览按操作类型列出源路径、目标路径、变更类型、数量及相关策略说明。融合与结构构建显示复制和复用关系；隔离显示用户策略及无法清退的对象。只有存在有效待执行项时才出现执行入口，执行使用已经冻结的计划，不从此时列表行重新推导目标。

操作历史独立于当前预览，用于查看实际事务状态。拒绝建议或取消预览仅改变方案状态，不对资料执行反向操作。撤销遵守事务类型与冲突规则，不把“历史里有记录”解释为所有动作都能完整撤销。

1.0.1 已有统一预览、执行确认和历史视角；历史详情、逐项阻断原因的可读性和大计划浏览体验仍需 Windows 实机验收，不能仅以核心测试通过作为界面验收结论。

## 8. 后台任务、取消与关闭〔UI-08〕

| 状态 | 可执行交互 | 禁止或限制 |
|---|---|---|
| 未扫描 | 选择范围、开始扫描 | 不允许从空库存生成整理计划 |
| 扫描／只读分析／预览生成中 | 查看进度；任务支持取消时请求停止 | 当前实现禁用范围、视角、搜索、列表和操作，避免任务上下文变化 |
| 停止请求已提交 | 查看“正在停止／等待当前读取返回” | 停止不表示工作线程已经结束，不可立即把未完成结果置为可执行 |
| 已确认的文件操作执行中 | 查看当前任务状态 | 当前实现不提供中途取消，关闭窗口需等待执行返回 |
| 任务成功返回 | 查看对应结果或预览 | 仅在任务完整完成时显示正常完成状态 |
| 任务错误返回 | 查看错误、保留适用的历史证据、按提示重试 | 不伪造成功，不恢复失效计划 |

1.0.1 的扫描、字节核验和主要只读分析在工作线程中执行；UI 每约 250 ms 读取最新进度快照。是否可取消由任务能力决定，并非每一种预览生成都支持立即取消。大文件内可检查停止，但同步操作系统读取若阻塞，需等待调用返回。

关闭可取消任务时，先询问是否停止后退出，等待工作线程结束后销毁窗口。执行写操作时不直接销毁窗口。新扫描开始会清空旧库存和旧计划；该次扫描取消后，不恢复旧计划或重新启用旧写操作。

## 9. 不完整结果与操作后过期〔UI-09〕

“扫描不完整”与“结果已过期”是两个不同维度。前者指本次范围有未成功读取或状态异常；后者指结果生成后发生了文件变更。两者都必须在观察结果中显式出现，不能用一个绿色完成条掩盖。

读取异常时，可以观察成功读取的对象及错误；目录内容未完整读取时不得宣称相同目录树。各计划按照其完整性前置条件决定能否生成和执行；菜单显示不是完整性证明。多盘任务中某盘失败，也必须在扫描问题中保留其信息。

隔离、重命名、归档、融合、结构构建、撤销的执行返回后，当前快照标记过期。成功、部分成功、返回失败，以及写任务抛出的异常均采用这一处理：清除派生计划和分析状态，转到历史，提示“未自动重扫”。过期结果可供查看、选择、打开对应位置与导出；进一步分析和文件写入需显式重新扫描。

该规则避免一次小操作触发隐式全盘 SHA-256 重读，也避免使用部分变更前的快照继续操作。它不代表已经实现增量刷新。用户可以选择较小目录重扫；切换单盘／多盘视角不得绕过过期标志。外部程序修改文件不会立即推送到界面，因此执行器仍需按计划策略验证当前文件状态。

## 10. 界面验收与后续能力〔UI-10〕

### 必须执行的 Windows 验收

1. 初次启动没有自动扫描；未勾选的盘不参与读取；旧侧栏、目录树和隐藏旧模式控件均不存在。
2. 大文件读取时进度前进；枚举阶段使用活动条；速度、时间、当前文件及读取异常保持可见。多盘 ETA 写明当前盘与阶段。
3. 搜索从甲文件切换到乙文件，即使两者占相同行号，选择也不转移；排序、后台完成和返回单根后逐一核对预览中的真实路径。
4. 对 A/B 执行评估和融合预览，不读取无关第三目录；参数取消和只读预览不修改资料。
5. 生成新预览失败后，旧计划不可执行；编辑映射后必须重建预览。
6. 写操作成功、部分失败或异常后，不自动全盘重扫；结果变为过期；历史可看，旧计划失效；切换视角不能重新启用写入。
7. 从过期状态开始新扫描，取消后不能恢复旧计划；关闭扫描和关闭写任务分别遵守上述生命周期规则。
8. 截取、全选与 CSV 导出范围表述一致；中文长路径及最低窗口尺寸下仍能读清关键信息。

已有 `smoke_gui_windows.ps1` 覆盖旧控件不存在、范围模式、中文夹具扫描、原生进度完成值、候选筛选、选择不转移、显式核验和结构预览等路径。该脚本在本轮只完成语法、内嵌 C# 编译与静态对照，**尚未在 Windows 实机执行**；写后过期、故障路径与多 DPI 布局仍需补充人工验收。
