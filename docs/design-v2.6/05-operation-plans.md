# 05 — 结果操作、计划一致性与恢复

**基线：v2.6；实现对照：DiskCurator Native v1.0.1；修订日期：2026-11-20。**

本文规定从观察结果到文件操作的完整流程。基础、主题和智能操作共享同一条“确定对象与范围 → 生成计划 → 检查预览 → 确认执行 → 查看结果与历史”路径。观察结果、相似性建议、目录映射和操作计划分别表达不同事实，不能互相替代。

“设计要求”是产品应满足的行为；“v1.0.1 对照”表示已在源码中找到对应实现。除特别说明外，源码对照不代表 Windows 实机验收通过。实际执行过的测试以根目录 [RELEASE-ACCEPTANCE.md](../../RELEASE-ACCEPTANCE.md) 为准。

## 1. 操作对象、范围和证据

### ACT-01：写操作必须有明确的单根范围

用户可以共同观察多个已选磁盘的结果，但 v1.0.1 的文件变更限定在一个已扫描根内。多盘结果中选定同一根的对象后，进入该根的操作范围并复用库存；跨根混选不得自动转为跨盘复制、移动或隔离。进入单盘范围不是重新扫描请求。

每个操作对象由来源根和扫描时的相对路径确定，不能仅保存列表行号。按钮、右键菜单和双击入口必须经过同一范围与状态检查。空选择、已隐藏或失效的选择、系统工作区路径、越界路径不得成为隐含目标。

选盘模式冻结盘符对应的卷类型、序列号，以及可取得的卷 GUID，在扫描前后及使用该范围时核对；同一盘符换成另一卷，不能继续使用旧库存执行。手动目录模式检查输入的规范化路径仍与扫描根一致，执行器还检查根与路径组件是否可用、是否发生重解析等变化。**当前手动目录模式没有与选盘模式完全相同的持久卷身份契约**，不能声称仅凭路径字符串已经证明物理设备身份。

目录 A/B 评估可包含当前扫描根及其子目录；融合只能使用根内两个互不包含的普通子目录。清退不能直接选择扫描根或事务工作区。

### ACT-02：操作必须保留证据等级

| 证据或状态 | 能表达的结论 | 对操作的影响 |
|---|---|---|
| 本次完整扫描的大小和 SHA-256 相同 | 同哈希候选 | 可生成候选隔离计划；执行采用用户选定策略 |
| 目录结构签名相同 | 同树哈希候选 | 可作为观察入口；不能直接宣称目录字节已核验 |
| 本次显式分析中逐字节比较相同 | 已核验的内容关系 | 可用于精确目录比较、融合及结构分析 |
| 库存不完整、相关读取失败 | 结果存在缺口 | 不输出可靠的完全相同目录结论；当前相关规划入口要求库存完整 |
| 文件操作后快照过期 | 操作前的历史观察结果 | 保留只读参考；不能继续驱动新分析或写操作 |

基于哈希的规划适配器只在私有库存副本中构造候选身份，不向原观察库存写回“已字节核验”。执行一次所选文件隔离，也不意味着整个磁盘所有候选都已经被精确核验。

## 2. 用户可配置的副本策略

### ACT-03：默认值不能变成不可修改的限制

`RetentionPolicy` 随隔离计划冻结。用户可以配置以下三个互相独立的维度：

| 设置 | 默认值 | 允许范围与实际含义 |
|---|---|---|
| 最少活动保留数量 K | 2 | 0～32；K=2 是默认值，不是系统硬性要求 |
| 是否要求不同文件对象 | 开启 | 开启时，多个硬链接路径不能冒充多个独立文件对象；关闭时允许按不同路径计数 |
| 隔离前是否再次逐字节复核 | 开启 | 开启时比较所选待隔离文件与计划保留者；关闭时使用本次完整扫描 SHA-256 与文件大小、修改时间等状态核对 |
| K=0 的单次明确同意 | 关闭 | 允许活动目录中不再保留该组内容；仍只进入隔离区，不产生永久删除能力 |

不同文件对象不等于不同物理磁盘。副本数量必须说明采用的是路径数量、独立文件对象数量还是已核验数量，不能把同盘副本数描述为抗整盘损坏的备份能力。

快速模式降低的是重复隔离、目录清退执行前的内容复核等级。它不允许以抽样替代主扫描完整 SHA-256，也不自动关闭融合和新结构复制过程的正确性检查。扫描后若内容改变但大小和时间被恢复，快速模式可能无法识别；界面须在选择该模式和执行相应计划时明确提示。

K=0 需要单独确认，确认不能作为跨会话的永久授权。没有保留者时不存在可比较的保留副本，即使“字节复核”选项开启，也不能显示“已验证零份副本”的内容保障结论。源路径和快照等检查仍然存在。

**当前能力边界：** K=0 调整的是既有重复候选隔离流程的保留要求，不会把“隔离重复”变为任意文件删除。v1.0.1 的手动隔离仍要求所选文件属于重复候选组；目录清退遇到不属于重复组的唯一文件仍列为阻断项。产品不提供永久删除，隔离也不释放磁盘空间。

## 3. 手动隔离、批量整理与目录清退

### ACT-04：所选对象和当前范围必须分开表达

| 入口 | 用户确定的范围 | 计划包含的内容 | 不满足策略时 |
|---|---|---|---|
| 隔离所选文件 | 文件或副本视角中选定的具体路径 | 只列入所选文件；保留者从相应候选组中未被选中的活动文件选择 | 拒绝该次选择，不悄悄增加或减少用户选择 |
| 按策略隔离当前范围的多余副本 | 当前单根库存 | 按候选组选择 K 个合格保留者，其余生成隔离项 | 不具备足够保留者的组不产生隔离项 |
| 清退选中目录 | 一个普通目录及其后代文件 | 逐文件检查，保留者必须在该目录之外 | 列出阻断文件，保留原样；不能把部分清退称为目录已清空 |

规划使用已扫描候选分组，不先强制逐字节核验整个根。默认执行时读取的是本计划待隔离文件及其保留者；未涉及的候选组不应被顺带进行内容比较。独立性检查可能查询相关文件对象，但不是再次全盘哈希。

隔离计划须展示源路径、隔离目标、各项保留者、K 值、计数规则、内容复核方式，以及阻断原因。保留者不得位于隔离区，不得同时属于本次待移动集合，也不得被算作被清退目录之外的副本却实际仍在该目录内。

重命名和归档同样生成移动计划；名称规则、目标路径和匹配范围必须在预览中确认。目录重命名不等于递归重组；“当前范围归档”不等于只处理选中的一行。

## 4. 两目录评估与增量融合

### ACT-05：相似性报告和融合计划分离

用户可以在目录视角选定两行，也可以手工输入相对于当前扫描根的 A/B 路径。评估输出包括共有内容出现次数、覆盖率、相同相对路径、同名异内容、单侧独有及目录树是否相同。名称、年份和修改时间不能单独确定内容相同或融合方向；报告中的建议方向仍需用户确认。

v1.0.1 的 `evaluate_hashed_directory_pair` 和 `plan_hashed_directory_merge` 构造 A/B 子树并集，保留原根及相对路径，仅对此范围做临时内容分析。父子目录用于评估时共享后代只纳入一次；融合提前拒绝相同目录、扫描根、父子关系或系统工作区。

**范围限制须准确表述：** 当前实现仍要求原始 `Inventory.complete()`。无关文件不参与 A/B 内容读取，并不意味着根中已有的扫描错误会被忽略；“按子树单独判断完整性并放宽入口”尚未实现。

融合是来源 A 向目标 B 的增量复制：

| 相对路径和内容情况 | 计划行为 |
|---|---|
| B 不存在该项 | 创建缺失目录或复制文件，包含空目录 |
| 两边同路径、内容已经核验相同 | 跳过复制，并记录待执行前再次检查的同内容对 |
| 同名异内容或名称占用冲突 | 保留已有目标，来源版本采用不覆盖的目标名称 |
| 已经融合过的冲突版本 | 识别可复用内容，避免再次生成相同冗余副本 |

预览展示复制清单、新目录清单、跳过数与冲突数。执行前核对 A/B 两侧结构和文件元数据快照，并重新比较已跳过的同内容对。新文件先复制到软件暂存区、比较实际字节、请求落盘，再以不覆盖方式提交；原目录不被删除或移动。

## 5. 目录重组映射

### ACT-06：映射必须可审查、可修改且不隐含清退

智能重组先生成只读建议，用户可以拒绝、修改顶层目录映射，或指定单个原文件的准确目标。明确的文件级目标优先于自动归类；修改映射后旧执行计划失效，必须重新生成预览。预览按“原路径 → 目标路径”展示复制与复用关系，包含冲突处理和容量。

当前 `StructurePlan` 在当前根内构建新的顶层输出目录。相同内容可以由多条原路径映射到同一目标，但每条原文件到目标的关系都要能核对。执行前检查根快照、来源内容变化及已复用目标，复制后核对最终映射；已有目标不能被静默当作空目录或被覆盖。

结构构建的作用是生成新组织方式，不会自动删除旧结构，也不会自动触发目录清退。旧目录是否清退，需要用户单独选择，并按当次副本策略生成另一份计划。

## 6. 预览冻结与外部变化

### ACT-07：执行内容必须与确认的计划一致

计划生成开始时冻结当前根、路径、操作参数和副本策略。成功预览后，执行使用该份计划副本，不临时读取全局设置替换计划内容。

当前 GUI 的副本设置修改不会自动重写现有 `pending.retention`：已存在的计划继续使用预览时的策略，执行确认展示计划自身的 K 值和核验方式。若要把新设置用于当前操作，应重新生成计划。不得把“当前设置”与“待执行计划的设置”混为一谈。

开始生成新计划、修改映射、重新扫描、切换范围或放弃当前工作范围时，须按相应入口清除旧计划或明确确认放弃。新计划生成失败，不能继续把旧计划作为刚生成的结果执行。没有变更项的预览，不提供可执行的空操作。

执行前按操作类型检查必要状态：

| 操作类型 | 一致性检查 |
|---|---|
| 文件移动或重命名 | 来源仍为预期类型，大小、修改时间等快照一致，目标未被占用 |
| 目录移动或重命名 | 目录内相对文件/目录集合和文件元数据仍与预览快照一致 |
| 隔离 | 来源快照、保留者存在性和数量；按用户选项检查独立文件对象及字节内容，或核对扫描哈希证据与元数据 |
| 融合 | A/B 结构快照、跳过内容对、复制来源状态、目标未占用 |
| 新结构构建 | 当前根快照、来源内容变化、复用对象、最终映射 |

这些检查防止普通的预览后变化被静默吞掉，但不是对外部恶意并发篡改的全文件系统原子快照。源或目标发生不一致时，拒绝旧计划并说明需要重新扫描和预览，不能临时替换目标继续执行。

## 7. 执行、日志与恢复

### ACT-08：移动事务和复制事务分别定义失败语义

文件修改由执行器负责，观察视图不直接移动用户文件。Windows 执行器按当前根取得命名互斥锁，并检查软件工作区及未完成事务。路径不得逃出当前根，既有目标不得被覆盖；重解析路径及不可信工作区状态不能通过普通操作继续使用。

事务工作区为根内的 `.DiskCurator-System`，包括日志、暂存和隔离目录。扫描和预览不会因此创建文件变更事务；主扫描写入可重建索引缓存不属于用户资料变更。

| 阶段或结果 | MOVE 类事务：重命名、归档、隔离 | COPY 类事务：融合、新结构构建 |
|---|---|---|
| `PENDING` | 记录来源、目标与暂存映射后开始暂存 | 记录复制和建目录任务后准备暂存副本 |
| `STAGEDALL` | 已暂存，隔离按计划策略再次核查保留者 | 待提交副本已完成复制和核验 |
| `DONE` | 全部移动提交成功 | 新副本和目录提交成功；结构构建还核对映射 |
| 发生失败 | 尝试按日志恢复原位置；成功记录 `ROLLBACK` | 清理未提交暂存文件，保留已提交完整副本，记录 `PARTIAL` |
| 恢复遇到占用、损坏或不可信状态 | 记录或报告 `RECOVERY_FAILED`，要求人工检查 | 同样进入需要人工检查的状态，不删除已可见副本来伪造全回滚 |

不能把 COPY 的 `PARTIAL` 显示为“全部回滚”，也不能仅因出现错误就认为用户数据完全未变。已有待人工恢复事务时，后续写操作应被阻断；重新扫描不是修复损坏事务日志的替代办法。

上述设计对正常错误、进程中断提供可追踪的恢复路径。突然断电、USB 掉线、文件系统损坏及真实磁盘持久化行为仍需 Windows 与实际介质验收，不能由可移植测试推导绝对原子性。

## 8. 撤销能力

### ACT-09：只显示当前事务真正支持的撤销

MOVE 类成功事务可构造反向计划，将已提交路径移回原位置。若原位置已被用户占用或工作区不可信，撤销会拒绝覆盖。撤销本身也是新的受检查操作，并写入事务状态。当前移动日志没有保存可恢复的完整文件内容版本；撤销不应被描述为内容版本回滚，也不能保证识别所有操作后的内容修改。

融合和新结构构建的 COPY 类事务不通过普通 Undo 自动删除新增文件。需要移除其中内容时，应重新扫描后按用户配置的策略另行生成隔离计划。界面须在执行前说明这一点，不能使用笼统的“所有操作可撤销”。

当前 `undo_latest` 找到最近一笔可识别的已完成事务；若该笔是 COPY 类，会返回不支持自动删除的说明，不会静默跳过去撤销更早的一笔。GUI 的撤销也受“结果未过期”条件约束，写操作后需显式重扫再请求下一次写操作。

## 9. 取消、异常与过期结果

### ACT-10：取消分析和中止写入不能混为一个动作

扫描、精确核验、A/B 分析和部分预览任务可以请求取消。大文件扫描和内容比较按块检查取消；某些规划阶段只在阶段边界检查，不能承诺任意指令瞬间终止。操作系统阻塞的同步读取仍须等待调用返回。取消只读任务不能创建文件变更事务，也不能恢复已失效的旧计划。

v1.0.1 的正式 Apply、MergeApply、StructureApply、Undo 没有中途取消接口。界面在这些任务期间禁用停止，并要求等待后再关闭窗口。若后续增加可取消写入，必须同时定义提交边界、恢复语义和测试，不能直接把扫描取消标志接入提交循环。

任一文件变更任务成功、部分成功、返回失败或抛出异常后，GUI 均清除派生计划并把当前扫描会话标为“结果已过期”：

- 旧文件、目录快照保留为只读参考；查看位置、导出及操作历史仍可用，导出注明过期。
- 新的分析、计划或写入被阻止；返回多盘结果或切换视角不能清除过期标记。
- 不自动重新读取整个磁盘。用户显式选择原范围或较小目录重新扫描后，才能继续分析和整理。
- 新扫描开始即丢弃旧库存与旧计划；新扫描被取消或失败，不能恢复旧计划为可执行状态。

可信的操作后增量刷新、跨次缓存跳过和中断续扫尚未实现。当前“结果过期 → 显式重扫”是明确的产品行为，不应写成已有自动增量更新能力。

| ACT-08 分类型事务恢复 | `execute_plan / recover_copy_tx / recover_incomplete` | `test_recovery / test_merge / test_structure`；Windows 设备故障验收未完成 |
| ACT-09 有边界的撤销 | `undo_latest` | MOVE 撤销和 COPY 拒绝行为的核心回归；历史选择及提示需 GUI 验收 |
| ACT-10 取消与过期结果 | 扫描取消参数；GUI `results_stale / complete` | 块内取消回归；写入失败、异常、切换视角和新扫描取消后的 UI 状态需实机验收 |

## 11. 当前实现差距清单

以下是 v1.0.1 的实现边界，不得改写为用户永久不需要的能力，也不得仅修改文字就视作已经解决：

- **ACT-01：** 手动目录模式尚未统一到选盘模式的卷身份核对；跨根写操作未实现。
- **ACT-03 / ACT-04：** K=0 仍受当前重复候选隔离入口约束；唯一文件不能通过该入口处理。普通手动文件管理的更广删除或隔离能力需单独设计，不能把这项实现限制当作用户的永久要求。
- **ACT-05：** A/B 虽只读取选定子树，入口仍要求整个原库存完整；按子树单独判定可分析性未实现。
- **ACT-07：** 设置变更保留既有计划策略，当前没有“自动以新策略重算所有待执行计划”的能力。预览与执行必须显示冻结策略，避免误解。
- **ACT-09：** 普通 Undo 只支持适用的 MOVE 事务，不提供内容历史版本恢复，不自动删除 COPY 事务结果。
- **ACT-10：** 写任务不可中途取消；操作后没有可信增量刷新，新的写操作前需要显式重扫。读取任务块内取消不能代表写事务已有取消能力。
- **ACT-01～ACT-10：** 本文对应的 Windows GUI 状态流与真实移动硬盘故障场景尚未完成实机验收。
