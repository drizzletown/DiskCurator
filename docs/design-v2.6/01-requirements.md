# 01 — 产品需求与功能体系

> 1.0.2 交付补充：G-01/G-02/G-04 已补齐；缓存状态新增独立字段，CSV 带范围和状态。本文关于 1.0.1 的现状审计保留作对照，最新实现与验证以 [交付记录](../../RELEASE-ACCEPTANCE.md) 为准。

## 1. 使用场景与目标

主要场景是整理一块或数块用户明确选定的移动硬盘：文件数量多、备份批次多、命名不统一、多个目录部分重合，并且经常需要人工判断保留哪一份。

典型任务包括：查找某文件的重复副本；比较两个历史目录；将较零散备份中的独有内容补入目标；查看目录容量与重复程度；先构建新的组织结构，再另行决定是否清退旧目录。工具应持续回答“正在处理哪里、处理了多少、预计还要多久、结论覆盖哪个范围、这次操作会改哪些对象”。

## 2. 产品级要求

| ID | 规范要求 | 约束与完成判据 |
|---|---|---|
| P-01 | 以扫描结果组织全部整理流程 | 修改用户资料的动作从结果选择或明确范围发起，统一进入计划；基础/主题/智能不再是模式切换 |
| P-02 | 扫描范围由用户明确指定 | 默认选盘模式且零预选；手动模式指定一个目录；不扫描未选择的数据根 |
| P-03 | 主扫描完整记录内容哈希 | 所有符合扫描规则且可读的普通文件，包括空文件和唯一文件，记录完整 SHA-256；失败可见 |
| P-04 | 观察和建议不修改资料 | 缓存写入用户应用缓存；仅观察、菜单、预览不创建数据事务或修改原文件 |
| P-05 | 基础管理能力可独立使用 | 用户无需先运行全范围智能分析，便可选择对象、指定 A/B、生成相应预览 |
| P-06 | 结论具有范围和证据等级 | 副本数、相似度、异常与截取范围明确；候选和实际字节验证不能混称 |
| P-07 | 修改前预览与确认 | 计划对象、源/目标、冲突和策略可审阅，执行使用冻结的计划；影响计划前置条件的文件或范围变化使旧计划失效或拒绝执行；策略设置不静默重写已冻结计划 |
| P-08 | 对长任务有可观察性 | 进度、时间、当前路径、错误和可取消状态可见；不得数小时无反馈 |
| P-09 | 操作后不隐式全盘重扫 | 当前快照过期，用户决定何时、以什么范围重扫；未实现增量更新时不能伪装实时结果 |
| P-10 | 实现与验收如实表达 | Windows 实机、Linux、编译、静态审查和微基准证据分别记录 |

选择磁盘时当前支持可读取的本地固定卷和可移动卷。未准备就绪的设备、网络位置与不支持的类型不得被静默扩展为扫描对象。手动目录入口是否接受具体路径，以实际根验证结果为准，不由盘符名称推断物理介质。

## 3. 功能体系

| 功能域 | 能力 | 主要结果 |
|---|---|---|
| 范围与库存 | 选盘/指定目录、枚举、完整 SHA、异常与索引保存 | 每根 Inventory、多根 FullScan |
| 文件观察 | 大小、类型、路径、哈希、候选/精确副本 | 文件记录与副本成员 |
| 目录观察 | 目录大小、文件数、目录树候选、空目录参与 | 目录记录与树指纹候选 |
| 目录关系 | 指定 A/B、内容覆盖、包含、相对路径冲突、相似发现 | 可解释比较报告 |
| 基础操作 | 选择、查看位置、隔离预览、命名、导出、策略、历史 | 单根计划和记录 |
| 主题操作 | 重复副本整理、融合、旧目录清退、类型/日期归档、照片 | 有明确输入范围的任务 |
| 智能操作 | 融合建议、结构规则、逐文件映射编辑 | 可拒绝建议及复制计划 |
| 执行与恢复 | 冻结计划、前置复核、暂存、日志、提交、可支持的撤销 | 成功/部分成功/失败记录 |
| 性能与诊断 | 分阶段进度、I/O 与内存记录、只读基准 | 可定位瓶颈的测量结果 |

“基础操作可独立使用”不等于所有文件管理功能已经完成。当前重命名使用一个文件或一个目录下的规则；当前隔离入口针对重复候选，K=0 也尚未开放为任意唯一文件删除。它们是 1.0.1 的操作范围限制，不能反向写成用户不允许手动管理唯一文件。

## 4. 观察指标定义

| ID | 指标 | 定义与显示要求 |
|---|---|---|
| OBS-01 | 文件大小与目录容量 | 文件逻辑字节和目录下普通文件逻辑字节累计；不是实际物理占用、可释放量或不同对象独占容量 |
| OBS-02 | 文件候选副本数 | 在说明的扫描范围内，大小和完整 SHA 相同的路径出现次数，包含自身；哈希失败显示未知 |
| OBS-03 | 目录树候选副本数 | 将直接文件名、大小、哈希及子目录名称/签名组合得到的相同树候选数；包含空目录；外层目录名可不同 |
| OBS-04 | 已验证副本数 | 在实际字节比较的分析范围内，已确认内容组的成员数；不能沿用更大范围候选数并称为精确 |
| OBS-05 | 内容重合与相似度 | 指定 A/B 的已核验内容多重集重合、较小侧覆盖率、Jaccard、同路径异内容及独有项分别给出 |
| OBS-06 | 完整性与异常 | 不可读、变动、未哈希、受限/截断与缓存保存问题分别表达，不把未知目录计为“0份”或“无重复” |
| OBS-07 | 潜在冗余 | 如显示，必须注明基于候选和某个保留假设的逻辑估计；隔离不释放空间，不能显示为已经腾出的容量 |
| OBS-08 | 结果范围与时效 | 显示扫描根、观察计数范围、当前操作根、是否过期；导出保留必要的范围和状态说明 |

候选计数按路径计数，不自动应用“不同文件对象”策略。硬链接、多份同盘副本与跨物理磁盘副本是不同概念，不能用一列“副本数”同时承诺这三种含义。

1.0.1 的目录候选完整性判断较保守：一个根存在扫描错误时，该根目录候选数可整体降为未知。按子树隔离错误的细粒度可信状态尚未实现。

OBS-06 的缓存失败展示仍有实现差距：核心保留内存结果并发出保存告警，但告警不是 Inventory.errors，GUI 后续阶段可能覆盖该条文字。缓存持久化状态尚未形成持续可见的独立结果字段。

### 相似度的数学含义

设 A、B 的文件内容多重集分别为 M_A、M_B，按已验证内容身份计数；共有出现次数为：

`shared = Σ_c min(count_A(c), count_B(c))`

较小侧覆盖率为 `shared / min(|M_A|, |M_B|)`；多重集 Jaccard 为 `shared / (|M_A| + |M_B| - shared)`。分母为零时显示“不适用”，不强行给出 0% 或 100%。

相似度高不代表目录可互换、某一份更新或可以自动清退。相同内容位于不同相对路径、同名异内容、来源独有和目标独有必须分别呈现。自动建议可有证据阈值，但用户手动指定 A/B 不应被自动推荐阈值挡住；扫描有效性和目录范围限制仍需满足。

## 5. 观察结果与操作的关系

| 当前对象或视角 | 用户目的 | 操作范围必须如何说明 |
|---|---|---|
| 一个或多个文件 | 查看、选择、隔离预览 | 显示选定路径；保留者由当前根及冻结策略确定 |
| 一个目录 | 查看组成、改名、定向清退 | 改名规则的作用目录明确；清退只涉及其文件，保留者在整个被清退目录外 |
| 两个目录 | 评估、决定融合方向 | 对话框明确 A/B 和源/目标；内容比较仅覆盖两子树；融合拒绝重叠/不支持的根 |
| 重复候选组 | 人工选择副本或按策略整理 | “所选文件”与“当前根重复副本整理”分开命名；不能暗中扩成全根操作 |
| 全范围目录关系/智能建议 | 发现可整理的目录对 | 明示当前根，用户主动发起；结果限流或截断必须可见 |
| 目录重组映射 | 检查建议、编辑路径、构建新结构 | 展示来源→目标和 COPY/REUSE；不连带清退旧目录 |
| 操作预览 | 决定是否执行 | 显示冻结的对象、路径、策略与风险；更改映射需重建预览 |
| 历史或过期结果 | 追溯、参考、导出 | 不把过期快照作为新分析/写入的有效库存；适用的撤销仍须满足当前入口条件 |

跨盘总览中的选择必须先解析到当前操作根。跨根混选不得直接交给现有单根执行器，也不能将其他盘的候选路径当作本根事务已经验证的保留者。

## 6. 非功能约束与明确边界

性能目标分为“正确的工作量与范围”“可响应的界面”“固定介质上的吞吐与内存”三类，具体指标见 [03-scan-performance.md](03-scan-performance.md)。不得通过跳过完整哈希、隐瞒读取失败或改变用户策略来声称提速。

UI 主线程负责窗口和快照展示，耗时扫描/核验/计划计算由后台任务运行。当前大列表筛选仍有主线程计算与固定显示上限，不能宣称已经实现百万记录的任意分页或固定响应 SLA。

永久删除、跨根复制事务、自动定时整理、自动执行建议、跨次可信增量缓存和断点续扫不属于已实现的 1.0.1 功能。后续是否纳入及如何实施，按 [07-implementation-status.md](07-implementation-status.md) 单独推进。
