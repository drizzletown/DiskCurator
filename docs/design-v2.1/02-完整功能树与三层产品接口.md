# 02 清晰完整的功能体系（正式产品信息架构）

## 1. 五个业务能力域（唯一归属）

```text
DiskCurator
├─ A. 看清数据（盘点）
│  ├─ A1 递归扫描、错误和完整性
│  ├─ A2 空间/大小/类型/日期排行
│  └─ A3 搜索、筛选、CSV 导出
├─ B. 看懂关系（证据）
│  ├─ B1 精确相同文件
│  ├─ B2 完全相同目录树
│  ├─ B3 目录差异、包含、内容重叠
│  ├─ B4 跨层级历史备份关联推荐的证据
│  └─ B5 照片视觉相似候选（非精确重复）
├─ C. 想清方案（决策）
│  ├─ C1 融合候选与方向选择
│  ├─ C2 全根建议目标目录树
│  ├─ C3 目录/文件映射编辑
│  ├─ C4 全量操作影响与冲突预览
│  └─ C5 可隔离性及阻断原因
├─ D. 执行整理（受控写操作）
│  ├─ D1 两目录非破坏性增量融合
│  ├─ D2 非破坏性构建新目标结构
│  ├─ D3 批量重命名
│  ├─ D4 规则归档（类型/年月）
│  └─ D5 双副本条件下隔离多余内容/定向清退
└─ E. 保障可信（全局横切）
   ├─ E1 计划与源/目标复核
   ├─ E2 临时暂存、无覆盖提交、字节核验
   ├─ E3 根路径/链接/工作区/日志保护
   ├─ E4 恢复、撤销、操作历史
   └─ E5 测试证据、发布门槛
```

**归属规则**：推荐是 C 域，不与 B 域“关系事实”混淆；隔离在 D 域，双副本约束在 E 域；照片相似是 B5，但照片归档是 D4。相同内容识别只有一套 B1 证据，不为融合、清理各造一套。

## 2. 三层产品接口与依赖关系

| 层 | 展示内容 | 核心原则 | 对应业务域 |
|---|---|---|---|
| **L3 智能整理（默认）** | 六步向导、风险摘要、一条当前主行动 | 最大限度自动分析，操作必须确认 | A→B→C→D→E 全链路 |
| **L2 主题工具** | 一个目标、一段流程、必要的参数与结果 | 预组合底层功能，减少跨页跳转 | 任务相关能力集合 |
| **L1 基础工具** | 六类独立的文件/目录操作工作流，含人工管理与受保护执行 | 先建立可靠、可精确控制的能力；L2/L3 复用它 | A/B/C/D/E 各单能力闭环 |

三层是**同一能力的不同交互深度**，不是分别开发三套算法；内部调用路径一律为 `UI → Orchestrator → Domain Core → Safe Executor`。

## 3. L3 智能模式的唯一主路径

`选择与扫描 → 发现整理机会 → 审查建议结构 → 编辑映射（可跳过） → 预览并确认构建 → 结果复核`。

阶段 B “安全清退旧备份”应作为复核页的**另行申请动作**，绝不能成为“下一步”默认自动执行的写操作。

## 4. L2 七种主题任务（按用户意图，不按底层 API）

| 主题 ID | 用户要做什么 | 自动组合的能力 | 交付 |
|---|---|---|---|
| T-01 | 历史备份融合 | A1+B1+B3+B4+C1+C4+D1+E | 增量融合预览/结果 |
| T-02 | 重复文件整理 | A1+B1+C5+D5+E | 按内容组保留两份后的隔离方案 |
| T-03 | 照片整理 | A1+B5+C4+D4+E | 相似候选与按年月归档预览 |
| T-04 | 批量重命名 | A1+C4+D3+E | 筛选规则、改名对照、撤销 |
| T-05 | 旧备份安全清退 | A1+B1+C5+D5+E | 旧目录范围内的可隔离项与阻断项 |
| T-06 | 目录差异比较 | A1+B1+B3+E | 左右差异、包含/重合关系 |
| T-07 | 按规则归档 | A1+C4+D4+E | 类型/年月目标和逐文件预览 |

**目录体检不是第八个“工具按钮”**，它就是智能模式的入口和所有主题任务的前置条件。空间排行、CSV、历史记录属于上下文辅助能力；放在“详情/更多”，不作为首页并排主按钮。

## 5. L1 基础视图归并（保留底层证据，缩减导航）

原始 13 个视图需要收敛为 5 个分组（内部可以继续复用已有数据源和兼容视图）：

1. **文件与空间**：全部文件、文件夹大小、文件类型、筛选/排序、导出。
2. **重复与目录关系**：重复文件、重复目录、目录关系、目录比较、备份安全。
3. **照片与元数据**：相似照片、EXIF 状态。
4. **建议与计划**：融合建议、建议目标结构、操作预览、逐文件映射。
5. **操作与恢复**：历史、隔离、撤销、恢复/异常信息。

原有 13 个内部视图不等于未来必须给用户看到 13 个标签。新增“基础工具”页面应按分组进入详细页；开发者兼容标签可以保留为不可见状态存储。

## 6. 不能再出现的功能组织方式

- 禁止把“扫描、比较、目录关系、自动建议、融合、结构建议、编辑映射、预览、执行”全都放在同一行工具栏。
- 禁止把“推荐融合”“融合目录”“按建议结构迁移”写成三个没有关联的入口和不同的算法。
- 禁止把“隔离重复”“清退旧目录”误写成永久删除或释放空间。
- 禁止让“智能整理”丢失底层功能，但也不应让普通用户先看懂 13 个数据页才能完成一次整理。
- GUI 不负责判断硬链接独立性、内容相等和安全删除；这些必须只在领域核心/执行器判断。

## 7. 功能成熟度与产品可见性的关系

“已写代码”可以显示为测试/预览能力；“Windows 测试通过”可以进入候选发布；只有高风险保护和端到端证据足够，才可作为正式版默认写操作。数据安全未验收时须呈现保守警告或隐藏危险入口，而不是用 UI 文案掩盖质量差距。


## 8. v2.1 新增规范：六项可独立使用的基础能力

| 基础 ID | 独立入口 | 工作流程 | 当前 rc8 代码状态 |
|---|---|---|---|
| BF-01 | 文件与空间 | 目录选择→扫描→过滤/排序→文件定位/报告 | 既有能力；独立复制/移动尚待完善 |
| BF-02 | 精确重复文件 | 结果分组→人工多选待隔离项→双副本安全计划→二次确认→撤销 | 已实现人工安全隔离 API 与 Win32 入口，Windows 待验收 |
| BF-03 | 完全相同目录 | 相同目录组→选中目录→范围外两份保留者核验→仅可清退项隔离 | 已复用范围清退 API 与 Win32 入口，Windows 待验收 |
| BF-04 | 相似目录发现 | 所有有实质内容重合的互不包含目录对→排序→查看详细报告 | 新增有界候选检索与明确截断提示，Windows 待验收 |
| BF-05 | 指定双目录评估与融合 | 人工选择 A/B→多指标证据→改方向→增量融合预览→授权复制→复核 | 新增双目录多指标评估，复用非覆盖融合事务；Windows 待验收 |
| BF-06 | 单项/批量受控操作 | 选择文件/目录→动作与目标→安全计划→执行/审计 | 重命名、归档、隔离既有；通用复制/移动尚未完成 |

**基础层是有能力的工具，不是六个仅供查看的页面。** 旧的五个证据视图组继续作为 L1 内部结果导航，但不可替代六项完整基础工作流。详见 `12-坚固的基础能力与手动管理规范.md`。
