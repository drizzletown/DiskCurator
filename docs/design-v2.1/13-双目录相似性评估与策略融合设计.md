# 13 双目录相似性评估与策略融合设计（v2.1 新增，规范性）

## 1. 完成目标

用户指定单根目录内的 `A` 与 `B` 两个互不包含的子目录，在完全不修改原文件的前提下得到**可解释的相似关系、差异清单和可编辑的融合方案**；在确认后执行复制并验证。人工指定一对目录是独立于“自动候选推荐”的基本能力。

## 2. 相似性不是一个未经解释的百分数

令 `M_A(c)`、`M_B(c)` 表示经完整字节核验的内容类型 `c` 在 A、B 的文件出现次数，交集文件数 `I=Σ_c min(M_A(c), M_B(c))`，`N_A=Σ_c M_A(c)`、`N_B=Σ_c M_B(c)`。定义：

- `cover_A=I/N_A`：A 内容出现项在 B 中可找到对应项的比例；
- `cover_B=I/N_B`：B 内容出现项在 A 中可找到对应项的比例；
- `overlap_min=I/min(N_A,N_B)`：较小文件集合的内容覆盖程度，适合发现增量备份；
- `jaccard_multi=I/(N_A+N_B-I)`：考虑多重计数的重合度；
- `path_agreement`：同相对路径且经字节核验相同的文件计数/适用比较基数；
- `path_conflicts`：同一相对路径存在，但字节不同的文件数量。

分母为 0 时应显示 `N/A`，不能误报 100%。共享内容种类数与多重集交集项要同时报告，避免多次复制同一文件夸大“相似度”。上述计算口径在 rc8 `DirectoryPairReport` 中已实现并通过 Linux 核心测试；Windows 环境仍待复测。

**重要**：`overlap_min=100%` 可能意味着“其中一个目录的文件内容在另一个目录被完全包含”，但不能推出目录树相同、两个目录可互换，更不能推出能删除一个目录。相对结构、空目录、异名内容、内容冲突仍要单独显示。

## 3. 双目录人工融合的三种策略

| 策略 | 用户目的 | 默认处理 | 需要特别说明 |
|---|---|---|---|
| S1 增量补齐（默认） | B 是想继续使用的主要目录 | A 有而 B 无的文件复制到 B；相同内容在 B 已存在可复用；同名异内容另存 | 不覆盖、保留 A；不等于 B 比 A 更新 |
| S2 保留相对目录结构 | 需要保持照片/项目原层级 | 尽量在目标对应路径保留来源层级及空目录 | 同内容不同路径可能产生多份文件；用户知情 |
| S3 合成独立新目录（规划增强） | 不想修改 A 和 B | 建立新 C，按映射汇集两侧文件与版本 | 需要新目标空间预算和独立执行验收；rc7 不可直接声称支持 |

S1 和 S2 不是安全等级差异；无论哪一种，精确内容判断和无覆盖提交相同。用户若明确不复制同内容第二份，也必须在映射表保留来源→目标关系。

## 4. 差异处理决策表

| A/B 状态 | 默认操作 | 用户可以做什么 | 必须保持的条件 |
|---|---|---|---|
| 相对路径相同、字节相同 | 跳过复制 | 仅查看来源对应 | 保留验证证据 |
| 相对路径不同、字节相同 | 映射复用或保留目录布局 | 选择采用 S1/S2 | 不能误计为两个不同内容 |
| 仅 A 有文件 | 复制到 B | 改目标路径或选择暂不复制 | A 不动；不可覆盖 B |
| 仅 B 有文件 | 保持 B | 可查看，不凭缺失自动“补旧” | B 不动 |
| 同相对路径、内容不同 | 同时保留两版 | 修改来源版的目标文件名 | 必须显示两版字节不同 |
| 文件或目录不可读 | 标记未知，阻断有关写操作 | 排除本次，或修复后重扫 | 不得假装已经核验 |
| 空目录差异 | 明确保留目录结构 | 可选择保留或在方案中说明排除 | 记录结构变化，不遗漏 |

## 5. 决策状态与执行权责

`选 A/B → 只读扫描/核验 → 查看多指标关系 → 选择方向及策略 → 逐文件差异与映射 → 编辑冲突 → 生成冻结计划 → 用户确认 → 复制核验无覆盖提交 → 结果复核`。

执行只允许修改用户明确选择的目标或新建目标，不允许删除 A、B 中任何源文件；B 中已有异内容数据也不覆盖。旧目录清退必须作为另一个隔离计划，且满足两份独立活动副本（对旧目录范围外两份）的更严格条件。

## 6. 可追溯报告结构

建议输出 `DirectoryPairReport {root, left, right, scan_id, valid, overlap_metrics, structural_metrics, identical_paths, content_shared, left_only, right_only, changed_same_path, unresolved, errors[]}` 和 `MergeDecision {direction, strategy, user_edits[], conflict_renames[], ignored[], frozen_plan_id}`。这是设计目标，不是 rc7 API 的已存在类名。

每个建议要显示“为什么”，并允许用户手工交换方向。对于系统推荐的 A/B，先展示同一份评估报告，不应另写一套推荐结果解释逻辑。

## 7. 最小验收样例

```
A/IMG_001.jpg = X    B/IMG_001.jpg = X
A/IMG_002.jpg = Y    B/IMG_002.jpg = Z  (同名异内容)
A/旧相册/IMG_003.jpg = Q
                     B/IMG_004.jpg = R
A/空目录/
```

必须报告：同路径同内容 1；同路径异内容 1；A 独有 1；B 独有 1；空目录差异 1。选择 A→B 增量补齐，默认复制 Q、保留 Y 为冲突版本、保留 B 的 Z 和 R，不覆盖 X。重复执行不增加新的冲突版本；取消计划保证零写入。要在 A 内删除任何文件仍需要完整的独立双副本证明，不能因为 B 里保存了 X 就删除 A 的 X。
