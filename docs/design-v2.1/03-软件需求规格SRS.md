# 03 软件需求规格说明书（SRS，v2.1）

状态说明：本文件定义**目标验收条件**，不等于 rc7 已经通过 Windows 人工验收。旧 v1.2 `FR-*` 编号保留，新增用户界面要求使用 `UX-*`，全局安全约束使用 `BR-*`。

## 1. 功能需求的完整唯一清单

| ID | 归属 | 规范性要求（“应”） | 核心验收点 | 优先级 |
|---|---|---|---|---|
| FR-001 | A | 根目录只读递归扫描，记录文件、目录、空目录和错误 | 文件数、字节、失败项与完整性；拒绝穿越链接 | P0 |
| FR-002 | A | 空间排行、大小/时间/类型筛选与排序 | 列表可定位相对路径；排序稳定、统计口径清楚 | P0 |
| FR-003 | B | 查找字节完全相同的文件 | 名称不同可同组；首尾相同中段不同不能误判 | P0 |
| FR-004 | B | 查找完全相同的目录树 | 相对目录/文件名、内容、空目录；不完整禁止肯定判定 | P0 |
| FR-005 | D | 批量重命名支持通配、查找替换、前后缀、编号，文件与子目录可选 | 预览目标冲突/保留名；失败恢复和撤销 | P0 |
| FR-101 | B | 比较两个子目录的相对路径差异、包含和内容重叠 | 左独有/右独有/同路径不同内容准确区分 | P1 |
| FR-102 | C | 主动推荐适合融合的不同历史备份目录 | 候选及证据、反证、不确定项、可调整方向 | P1 |
| FR-103 | D | 两目录非破坏性融合 | 缺失补齐、相同复用、不同版本另存、源不变、幂等 | P1 |
| FR-104 | C | 自动提出全根目标目录结构 | 给出完整目标树及可读理由，不凭扩展名强行拆项目 | P1 |
| FR-105 | C | 允许修改目录映射及单文件目标例外 | 编辑后重算计划、显式例外优先、拒绝目标覆盖 | P1 |
| FR-106 | C | 全量旧文件→新目标内容对应表 | 每源文件恰有结果；允许核验后的多对一；空目录可追踪 | P1 |
| FR-107 | D | 阶段 A 复制建立新结构 | 验证源与目标；原目录不动；失败显式 PARTIAL | P1 |
| FR-108 | D/E | 阶段 B 独立申请旧目录定向隔离 | 该旧目录以外至少两份已核验独立活动普通文件 | P1 |
| FR-109 | E | 操作日志、故障恢复、允许的撤销及异常阻断 | 不猜测、不覆盖、未知日志拒绝、可见失败项 | P1 |
| FR-110 | B/E | 备份安全视图显示唯一/两份/多份及不确定项 | 清楚说明单根目录、单盘限制 | P1 |
| FR-111 | A/C | 报告导出（数据视图及计划原→新映射） | 相对路径、目标、动作、阻断、验证结果可追溯 | P1 |
| FR-201 | B | WIC/EXIF 元数据与 dHash 相似照片候选 | 相似绝不能当字节相同；解码失败可见 | P2 |
| FR-202 | D | 按类型/拍摄年月制定规则归档计划 | 明确 EXIF→文件时间的回退策略；预览后执行 | P2 |

## 2. 三层交互与体验要求

| ID | 规范要求 | 可观察验收 |
|---|---|---|
| UX-001 | 首屏默认智能整理，仅显示根目录、状态和一个主行动 | 用户无需先选某种底层算法即可扫描 |
| UX-002 | 智能六阶段进度可见，已完成、当前、待执行可区分 | 每阶段主操作只与当前任务相关；不得通过“下一步”自动实施另一写操作 |
| UX-003 | 主题工具按七个目标提供流程，不展示底层 API 列表 | 历史融合、重复整理、照片、改名、旧备份清退、比较、归档均可抵达预览 |
| UX-004 | 基础工具按五个证据组呈现，不暴露 13 个并列标签 | 搜索、筛选、明细、导出、历史仍可抵达 |
| UX-005 | 推荐可拒绝、修改、看解释、再预览，且不产生数据写入 | 操作前后源树字节与目录数不变；工作区不创建 |
| UX-006 | 写入前清晰披露文件数、容量、冲突、可回滚范围、两份副本风险 | 用户能够回答“会复制多少、会动哪些原文件” |
| UX-007 | 工作中仅可安全取消允许取消的只读任务；写入时不能随意关闭 | 不造成程序放弃未完成的事务收尾 |
| UX-008 | UI 保持简洁、可缩放、可键盘访问，错误使用用户语言 | 1280×720、1920×1080、125/150% DPI 与 Tab/焦点验收 |
| UX-009 | 同一业务动作只保留一个主要入口，详情只在需要时展开 | 主界面不出现“17按钮 + 13标签”式并列控件 |

## 3. 安全业务不变量

| ID | 不变量 |
|---|---|
| BR-01 | 精确同内容为完整字节相同；其他元数据仅作筛选/建议 |
| BR-02 | 完全相同目录树须全量节点和相对路径一致，扫描不完整不可输出肯定判定 |
| BR-03 | 关系评分对相同内容的重复次数采用合理处理，忽略系统元数据伪重合证据 |
| BR-04 | 同名异内容默认保留不同版本，不自动判定版本优劣 |
| BR-05 | 计划执行后所有被清退内容在本次清退范围外仍有两份不同文件对象且字节一致的活动普通文件；若定向清退旧目录，须位于整个旧目录之外 |
| BR-06 | 不覆盖异内容目标，不向根目录外写入，不沿链接重定向写入 |
| BR-07 | 相同规划与相同来源重复执行应幂等，不复制出第 N 个冲突版本 |
| BR-08 | 更换根目录、来源/目标变化、映射修订后旧计划不可执行 |
| BR-09 | 隔离项不作为活动保留副本，隔离不会物理释放空间 |
| BR-10 | 任何未验证或不可读文件不能用于内容复用/删除安全证明 |
| BR-11 | 先提交并核验新结构，再可独立发起旧资料清退；不允许联动自动删除 |
| BR-12 | 不完整事务、恶意日志、工作区标识异常必须阻断后续写入直到安全处理 |

| ID | 要求 | 验收方式 |

| NFR-02 | Unicode 宽字符接口、中文路径、合法长路径、保留设备名/大小写冲突处理 | Windows 实盘用例与告警日志 |
| NFR-03 | 扫描/推荐/计划可取消或明确显示阶段；GUI 长任务持续响应 | Windows 真实文件集 + UI 响应观测 |
| NFR-04 | 路径、目录链接、文件对象身份、暂存区和日志边界受控 | 恶意路径与 junction 测试 |
| NFR-05 | 高风险操作二次确认；执行器独立重核文件；失败可审计 | CLI/GUI 同等安全行为测试 |

| NFR-07 | 发布只用 PASS/FAIL/NOT RUN/BLOCKED 证据，不用“应该通过” | 测试矩阵、命令、日志与构建 SHA256 |
| NFR-08 | 默认只读；任何文件写入都有授权、内容核验和结果日志 | 自动化/人工复测，异常任务专测 |

## 5. 需求验收通则

**正向**：成功路径产生可理解结果。**逆向**：同名不同内容、空目录、重复路径、硬链接、外部创建目标、扫描后修改源、不可读节点、权限不足、空间不足及程序中断必须表现为安全拒绝或明确部分成功。**版本证据**：具体测试必须注明 rc7/后续版本，不得沿用旧版本成功推定新版成功。

## 6. 与设计的关系

文件/目录事实由 `Inventory`/`Duplicates`/`Comparison` 提供；建议与计划由 `MergeSuggestion`/`StructureSuggestion`/`Plan` 等产生；所有写入统一走领域执行函数及其事务保护；产品入口由 Win32 应用协调层驱动。详细接口与测试对应见 `05` 和 `08`。

| ID | 要求 | 可验证条件 | 成熟度 |
|---|---|---|---|

| BF-REQ-02 | 用户能在精确重复组中自行选择要隔离的成员 | 列表多选→精确生成所选文件的计划；未选者不动 | rc8 核心与 UI 编码，Linux PASS |

| BF-REQ-04 | 对完全相同的目录组用户可以指定清退范围 | 任一文件在范围外无两份保留者时仅阻断该文件 | 复用既有核心与新 UI 入口，Windows 待验收 |
| BF-REQ-05 | 基础层主动列出有内容重合的互不包含目录对 | 含嵌套备份，显示覆盖/多重集 Jaccard，候选上限明确 | rc8 核心测试 PASS，Windows 待验收 |

本节要求是原 `FR/UX/BR/NFR` 的细化与补充，不替代已有安全不变量。
