# 01 用户场景、成果与边界

## 1. 根问题

多年反复备份造成同一批照片/录像/工作资料散落多处：不同目录可能包含相同文件、新增文件、删减文件、同名异内容的新旧版本，且同一文件可能在不同时期改过名。用户不清楚“哪份完整、哪份重复、应如何整理”，担心一次清理误删唯一的历史内容。

用户需要的是**最终可理解的资料结构 + 所有原内容的可追溯对应关系 + 能证明安全的操作结果**，不只是“查找重复文件”。

## 2. 主要用户故事及完成标准

| 用例 | 用户的自然语言目标 | 系统必须交付 | 不允许发生 |
|---|---|---|---|
| UC-01 一键体检 | “看看这个目录到底有什么” | 文件/目录数量、占用、扫描完整性、问题总览 | 只读扫描时创建目录/日志 |
| UC-02 历史备份 | “2022 和 2024 相机备份合在一起” | 内容重合证据、双方独有/冲突、推荐与增量融合计划 | 只凭年份认定新旧，覆盖同名版本 |
| UC-03 整体重组 | “给这整个目录规划新的结构” | 目标完整树、每个来源文件/空目录的映射及理由 | 默默遗失文件、把不同版本合为一份 |
| UC-04 自主调整 | “这几个项目不能被拆开” | 修改目录映射与文件例外、重新计算预览 | 用户编辑后自动恢复建议并覆盖决定 |
| UC-05 重复整理 | “多余的备份可以减少吗” | 内容组、副本数、可隔离/不可隔离理由 | 少于两份活动副本时清退 |
| UC-06 照片整理 | “按日期整理照片，找找相似照片” | WIC/EXIF 视图、相似候选、预览归档 | 凭 dHash 自动删除或断言完全相同 |
| UC-07 常规管理 | “给某一批文件编号/比较两个目录” | 可控重命名、比较与明细报告 | 无预览大批量改动 |
| UC-08 故障处理 | “程序中断了，哪些文件还在？” | 已完成/未完成/阻断项及可信日志 | 无提示覆盖、擅自删除暂存唯一文件 |

## 3. 用户最小知识负担

智能入口不能要求用户预先懂得“文件指纹、目录多重集、增量融合、Stage、事务日志”。这些概念作为详情中的解释，不作为操作门槛。用户只需知道：**选目录、看建议、可修改、确认执行、核对结果**。

系统应把复杂性**逐渐展示**：概览只谈成果/风险；建议页展示理由；遇冲突才出现文件级选择；基础模式为需要精确分析的人保留全部证据。

## 4. 操作范围

- 用户输入根目录 `R`；所有受控目标与工作区都在 `R` 下。
- 同一个根目录可能位于移动硬盘；软件不维护多个盘的长期离线索引。
- 只统计当前扫描中可访问、可验证的文件。`R` 之外有副本不能据此判断或计入安全清退。
- 两个不同路径可能是**同一个 NTFS 文件对象的硬链接**；不能当作两份独立保留者。
- 目录 junction、符号链接及其他 reparse point 是边界/风险，不递归追随。
- 不要求管理员权限；遇权限问题报告并拒绝危险动作。

## 5. 结果衡量

**完整性**：原内容是否全部有目标映射；空目录是否保留；冲突版本是否全部保留。  
**整理价值**：新结构是否可理解、关联备份是否集中、用户编辑次数是否合理。  
**安全性**：被拒绝的危险清退是否充分阻断；执行前后内容字节是否相同；故障后的状态能否解释。  
**效率**：扫描反馈、推荐时长、计划复杂度、UI 响应与错误提示。不能凭单个 Linux 合成压力用例声明实际移动硬盘性能。

## 6. 单盘两份的限制

“双副本保留”是**本软件对清退的最低文件对象安全约束**，不是“两块不同硬盘的容灾备份”。同盘损坏、误格式化、勒索软件可能同时毁掉两份。提示中应明确建议用户另有独立设备备份。当前项目不做跨设备验证。
