# DiskCurator 性能架构与验收基线（v2.1 附录 PERF-01）

状态：**性能专项实施约束（基于 v1.0-rc8 源码审查，2026-11-18）**。本文件不代表这些优化已经实现。

## 一、性能目标

使用场景：单一指定根目录可能含多级历史备份、数十万张照片、数 TB 数据；介质包括 USB 移动机械硬盘、USB SSD 和本机 NTFS SSD。必须让“查看现状”尽快可用，让“完全相同”的结论保持字节级严格，让修改计划执行前的复核绝不因加速而省略。

### 用户可感知的任务分层

1. **快速盘点**（只读）：列文件树、大小、类型、时间、空间排名，不读取普通文件内容；扫描不完整要显式报告。扫描过程中允许逐步展示结果和取消。
2. **候选发现**（只读）：按大小、路径、目录结构、廉价指纹筛出可疑重复或相似项。未做最终字节核验的结果必须标注“候选”，不得作为相同事实或删除依据。
3. **严格验证**（只读）：对需要展示“精确相同”的文件组、目录树、选定双目录逐项验证；文件内容指纹仅用于分桶，最终用逐字节比较确定相等。
4. **计划与执行**（可能写入）：用户批准后，对受影响源和目标重新执行安全检查及必要的内容核验。完整性保护优先于缓存命中率。

## 二、rc8 当前源码审查发现的瓶颈

| ID | 观察位置 | 影响 | 设计决定 |
|---|---|---|---|
| PERF-01 | `src/win_main.cpp` 中 `Task::Scan` 连续执行 `scan`→`deduplicate`→`duplicate_dirs`→`suggest_structure`→`recommend_merges` | 只想按大小查找也要等完整内容去重和建议计算 | UI 工作流分阶段呈现，元数据完成即开放空间视图；深度操作按需或延迟执行 |
| PERF-02 | `src/core.cpp` 中同大小文件经 sample→full_fingerprint→equal_bytes | 同尺寸大文件可能多次读取，USB HDD I/O 最昂贵 | 引入候选分桶与持久索引；复用同一次扫描的验证证据；不删除最终字节确认 |
| PERF-03 | `compare_dirs` 和 `evaluate_directory_pair` 为构建两个子树多次线性遍历全部 `Inventory` | 多次双目录比较随整个根目录规模扩大 | 一次建立目录→文件范围索引，选择两目录时只比较其子树；未验证其余文件不阻断这两个子树的可证明结果 |
| PERF-04 | `find_overlapping_dirs` 为每个文件构建所有祖先 posting，再进行目录对交叉计数 | 深层目录与广泛共享内容可能造成巨大候选空间，已有 2M 关联与 25 万目录对的硬性拒绝 | 倒排索引、内容频率权重与候选限流；“仅展示 Top K”明确标注，不能假报穷尽 |
| PERF-05 | 扫描期进度通知条件基于目录数量，去重期通知按完整大小桶计数 | 单个平坦目录或大文件会长时间缺少可信进度 | 计数/字节级进度、阶段名、当前文件与可取消状态；控制通知频率 |
| PERF-06 | 现有 `test_stress.cpp` 在同一进程内先创建 4040 个小文件、再扫描及计划 | CTest 的总耗时不是扫描耗时，且未覆盖大容量文件和冷盘 | 独立只读 benchmark，逐阶段计时并记录 OS 读量/内存，加入真实介质矩阵 |

## 三、缓存设计和信任边界

- 仅在指定根目录范围内建立持久索引。可用 SQLite 作为单文件索引实现，**它不应自动写在被扫描的个人资料根目录中**：优先写入 `%LOCALAPPDATA%\DiskCurator\Cache`，按绝对根路径与卷身份隔离，并提供清理控制。缓存是否采用 SQLite 属于实现决策，不改变 Win32 SDK GUI / C++17 技术路线。
- 每条缓存记录至少包含规范化路径、文件大小、mtime、文件对象身份（支持时包括卷 ID 和 File ID）、指纹版本、验证时间与状态；目录项分开索引。大小、mtime、File ID 相同只是缓存可复用条件之一，不能作为内容相同的永久证明。
- 将缓存定位为**定位候选与减少重复 I/O 的加速数据**。清退、重命名等敏感操作继续执行受影响文件的独立性与内容验证；二副本不变量不能被缓存绕过。
- 文件系统外部变化、卷更换、重解析点、索引损坏、版本升级、异常时间戳等触发精细失效或重新扫描；无证据时不产生相等结论。
- 优先保证缓存可删除、可重建、不会影响原文件。高并发扫描采用单写者与读快照设计，持久索引不会成为事务日志的替代品。

## 四、I/O 与计算调度

- 首先消除不必要的读取与重复遍历，再考虑线程数；使用每卷 I/O 调度器。对**单个 USB 机械 HDD** 默认至多一个重度顺序读取任务（可配置），避免随机寻道放大；对 SSD 使用有限并发，但要实测收益。
- 按文件大小分桶；对特定候选适当抽样；需要精确内容身份时再全文件验证。同一个会话内共享进度与内容证据，不重复计算。
- 各阶段具备 `Cancel` 和节流进度。保证 Worker 不阻塞 Win32 消息循环；ListView 使用虚拟列表，只绘制可见行；结果可分批载入和排序。
- 对目录关系图不能静默漏结果；超预算可只显示“部分结果，扩大范围需选择目录/缩小条件”，并提供明确的过滤或 Top K 模式。
- 复制融合采用受控缓冲、临时文件、核验、落盘与无覆盖提交；不得为了吞吐省去 Flush/安全检查，也不能以多线程造成目标路径竞争。

## 五、测量方法

本次加入**可选只读测量目标 `dc_benchmark`**。其输出每阶段 `elapsed_ms / process_read_bytes / peak_working_set_bytes / result`。`process_read_bytes` 是 OS 进程层面的逻辑读取量，不等于物理硬盘读量；缓存命中、设备缓存和其他进程负载需要单独记录。

Windows 运行：

```powershell
cmake -S . -B build-perf -A x64 -DDC_BUILD_PERF_TOOLS=ON -DDC_BUILD_TESTS=OFF
cmake --build build-perf --config Release --target dc_benchmark
.\build-perf\Release\dc_benchmark.exe "E:\照片" 
.\build-perf\Release\dc_benchmark.exe "E:\照片" --full
.\build-perf\Release\dc_benchmark.exe "E:\照片" --full --overlaps --pair "相机2022" "相机2024"
```

**特别注意**：`--full` 会按现有严格算法完整读取部分文件内容；在数 TB 数据的机械盘上可能运行很久。先运行只读元数据模式。命令不修改文件或创建事务目录。不要对高负载/不稳定 USB 盘做长时间基准。

## 六、验收数据集与可量化 Gate

| 数据集 | 存储介质 | 必记指标与通过条件 |
|---|---|---|
| 5,000 / 100,000 不同大小和时间的文件 | Windows NTFS SSD、USB HDD | 元数据时间、枚举数、内存峰值、报错；与 Windows 目录枚举基线比对；正常运行不卡住界面 |
| 10,000 张真实 JPEG/HEIC 混合 | SSD、USB HDD | 冷/热扫描对照、抽样与全量读取次数、照片耗时、格式失败；准确性不低于原版 |
| 100 GB 少数大文件（视频、归档） | SSD、USB HDD | 内容验证总读取字节、有效吞吐、I/O 并发；不能重复全文件读取而不解释原因 |
| 50,000 个同大小不同内容、含首尾相同中部不同 | SSD | 无误判精确相同，记录抽样和全文件读取量 |
| 大量同内容跨多层历史备份 | SSD、USB HDD | 相似目录候选生成时间与峰值内存，任何截断/拒绝必须清晰报告 |
| 不可读/被修改/断开/符号链接/超长路径 | NTFS 测试设备 | 安全拒绝、无已确认事实的误判、能停止且 GUI 不长时间无响应 |

性能指标分三级：**功能正确性 Gate 不可妥协**；体验 Gate 需要 UI 持续响应、有效进度与可取消；吞吐量 Gate 在固定硬件、固定测试集上与 rc8 逐阶段对照，采用 P50/P95、多次测量，记录固件、接口及冷/热缓存状态。正式阈值应在第一轮真实设备基线后冻结，不能拿当前 4040 个小文本文件的总 CTest 时间冒充真实扫描 SLA。

## 七、开发次序

1. 加入独立 read-only benchmark 与真实 HDD/SSD 测试记录（本轮提供工具，**未做 Windows 实测**）。
2. `ScanMetadata` 与 `VerifyContent` 任务拆分；元数据完成时可交互、结果渐进展示。
3. 子树索引与指定两目录专项分析，避免全根重复遍历。
4. 可重建的持久指纹缓存；清退前再验证，不改变零误删标准。
5. 相似目录倒排索引/限流与虚拟列表优化。
6. 故障注入、Windows 冷/热盘对比、长时间运行与内存稳定性验证；回归现有全部安全测试。

**状态边界**：rc8 尚未具有上述阶段化索引/持久缓存；本补充文件定义未来质量要求，不虚构性能提升。
