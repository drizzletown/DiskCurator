# 07 Win32 三层界面与交互设计规范（UI v2.0）

## 1. 设计目标

用户第一次打开 DiskCurator，应在 10 秒内理解三件事：它能帮我**找出混乱和重复**、**建议整理后的目录结构**，而且**不经确认不会修改文件**。界面有现代感但不牺牲 Win32 原生可靠性。以工作流为中心，不把每一个底层 API 做成一个按钮。

## 2. 信息架构与首页

```text
┌────────────────────────────────────── DiskCurator ──────────────────────────────┐
│ [根目录 D:\资料备份_________________] [选择目录] [开始扫描]  扫描状态: 就绪       │
├─────────────┬───────────────────────────────────────────────────────────────────┤
│             │  整理助手                                          [查看详情]     │
│ ● 智能整理  │  扫描 → 发现 → 方案 → 调整 → 执行 → 复核                           │
│   主题工具  │                                                                   │
│   基础工具  │  [总文件数] [总占用] [重复内容组] [可融合目录候选]                │
│             │                                                                   │
│             │  发现：2 组历史备份有重合；1 个未验证目录                        │
│             │  建议：构建“整理结果”目录，原目录暂时保留                         │
│             │                                                                   │
│             │                    [查看建议方案]                               │
│             │                                                                   │
│  安全状态   │  次级：查看报告 / 本次不整理                                      │
└─────────────┴───────────────────────────────────────────────────────────────────┘
```

主操作最多一个；同一屏同时保留必要的“返回/拒绝/查看依据”。扫描后不立即展示 20 个文件的复制清单，用户进入“影响预览”时才看到逐文件明细。安全告警与当前建议都用自然语言表达。

## 3. 智能模式六屏职责（必须相互区分）

| 阶段 | 一屏核心问题 | 主操作 | 次操作与可见证据 |
|---|---|---|---|
| 1 扫描 | 我选的是哪一个目录，扫描是否完整？ | 开始扫描 | 浏览；异常清单；任务进度/安全取消 |
| 2 发现 | 哪里乱了、能整理什么？ | 查看建议 | 占用摘要、重复组、融合候选、唯一文件风险 |
| 3 建议 | 软件建议整理成什么样？ | 审查目标结构 | 旧目录/新树并排、推荐理由、同名冲突 |
| 4 调整 | 我是否接受这种组织方式？ | 生成完整预览 | 修改目标树/目录映射/单文件例外、拒绝建议 |
| 5 执行 | 实际会复制哪些文件、要多少空间？ | 确认构建新结构 | 全量映射、冲突/风险、复制/复用数量、确认弹窗 |
| 6 复核 | 新内容完整吗、旧内容怎么办？ | 查看结果 | 已验证/部分完成/异常、历史；单独申请旧目录清退 |

**特殊场景**：扫描没有发现可融合历史备份，不应堵塞整个流程；仍可生成保守的结构建议。未完成内容核验时应展示报告但禁止以不完整信息生成高风险清退计划。

## 4. 主题工具的可见结构

“选择一项工作”：历史备份融合、重复文件整理、照片整理、批量重命名、旧备份安全清退、目录差异比较、按规则归档。每个主题最多包含“条件 → 分析/预览 → 确认/结果”三个可理解阶段。不把“执行计划”“目录关系”“融合建议”作为需要用户自行拼接的原子步骤。

例如历史备份融合：**选择或接受候选 → 看双方差异和冲突 → 选融合方向 → 预览 → 单独确认复制 → 查看结果**。不会自行启动旧目录清退。

## 5. 基础工具：五个分组而不是十三标签

左侧“基础工具”提供分组选择器；右侧显示详细结果与筛选。五组为“文件与空间”“重复与目录关系”“照片与元数据”“建议与计划”“操作与恢复”。可深入原 13 个底层视图，但默认不露出全部标签。

## 6. 导航行为与术语

- 返回到前一步时，保留用户已修改但未执行的方案；发生新扫描才提示方案失效。
- 明确使用“建立新结构”“隔离多余文件”，避免使用带删除歧义的“一键迁移/清理完成”。
- 同一业务动作在智能、主题、基础三层都复用同一个 `Plan` 与安全执行接口；不允许不同默认安全阈值。
- 对复杂且需要判断的内容显示“查看依据”“查看逐文件映射”，而不是在首页灌入每行文件。
- 输出报告与撤销按钮属于结果/历史上下文，不与扫描按钮并列成主导航。

## 7. 视觉与可用性

建议视觉主题：深海军蓝 `#0F172A` + 主内容近白 `#F5F8FC` + 青绿强调 `#15B899`。视觉目标是克制、可信，不靠渐变/花哨动画。正文 Segoe UI；大标题、数据卡片和操作区有明确层级；表格采用低对比度分隔及行悬停、列宽可调。

- 继续使用 Win32 SDK/Common Controls/GDI；高 DPI 测试必须覆盖 100%、125%、150%。
- 重点支持键盘焦点、Esc/Enter、Tab 顺序、弹窗聚焦、通知与长文本省略后的完整查看；颜色不是唯一状态提示。
- 扫描/分析长任务必须显示进度或正在执行的明确状态，避免界面无响应。
- 空状态应提供下一步动作，不显示调试表格、空白 13 标签或裸露的后台状态码。
- 目标树和源树的并排视图只在需要时展开；小屏幕下支持折叠而非固定占用三分之一宽度。

## 8. 当前实现与目标差距

`rc7 src/win_main.cpp` 已有三层侧栏导航、六阶段导引、隐藏旧标签、自绘配色、目标目录 TreeView 及操作预览；但实际逻辑仍以一个 `App` 及大量隐藏视图状态为中心，部分基本功能通过兼容 ID 驱动。此文档要求的**统一流程状态模型、五个基础分组、全面键盘/高 DPI 验收、简洁信息层级进一步精修**属于后续工作；不可假定都已实现。

## 9. GUI 验收场景

- 新用户空根首次启动→扫描→看摘要，不出现 17 个按钮/13 标签。
- 智能模式从扫描走到目标树和全量预览，全部只读，磁盘未出现新目标目录/工作区。
- 三层切换保持根目录和既有分析结果；所选功能不丢失。
- 搜索控件真实输入、回读、`EN_CHANGE` 触发筛选、清空后恢复，不以向隐藏视图发送消息伪造结果。
- 编辑目标文件路径后计划重算；拒绝不写；确认前中止不留下内容。
- 执行中控件状态合理；不可中断的写操作期间关闭窗口必须有安全行为。
- Windows 真实窗口在 1280×720/1920×1080、不同缩放/主题下无溢出、按钮遮挡、焦点丢失。


## v2.1 L1 基础层：可操作工具，不是只读资料页

保留深色侧栏三级入口；进入“基础工具”时，首个主操作是“查看当前数据”，但根据页面出现当前上下文操作：

| 页 | 当前交互 | 用户操作结果 |
|---|---|---|
| 重复文件 | Ctrl/Shift 多选行→“人工隔离所选副本” | 精确计划预览，不自动隔离 |
| 重复目录 | 选择目录行→“安全清退所选目录” | 对整个目录范围计算两份外部保留者，展示可隔离/阻断 |
| 目录关系 | 发现内容重合的候选目录对→选择一行→“指定两目录评估” | 统计摘要、左右差异，允许继续融合预览 |
| 目录比较 | 手动输入两条根内相对路径 | 不受智能推荐阈值限制；多指标、原始差异列表 |

尚待完善：文件/目录右键菜单、永久保护标记、批量单项复制/移动、统一双栏 A/B 交互、键盘可达性和 125%～150% DPI 视觉验收。这些不得误标已完成。
