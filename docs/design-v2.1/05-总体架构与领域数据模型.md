## 2. 核心对象和含义（按 rc7 API 审核）

| 领域对象 | 来源字段/函数 | 语义与边界 |
|---|---|---|
| `Inventory` | `scan(root, progress, cancel)`；`File`, `Folder`, `errors`, `bytes`, `complete()` | 根内扫描快照；`complete()` 仅指扫描错误为空，不等于所有图片可解析 |
| `Duplicates` | `deduplicate(Inventory&)`；`groups`, `errors` | 经内容识别的等价组；错误必须影响危险计划许可 |
| `DirGroup` | `duplicate_dirs` | 完全相同内部目录树集合 |
| `Comparison`、`Relation` | `compare_dirs`、`directory_relations` | 路径差异、内容包含与重合证据，不直接授权融合 |
| `MergeSuggestion` | `recommend_merges` | 互不包含目录的重合、同路径、冲突和启发式强度，不代表时间上的较新版本 |
| `MergePlan` | `plan_merge_dirs` | 来源/目标完整快照、待复制/跳过/新建目录和冲突 |
| `StructureSuggestion` | `suggest_structure`；`StructureRule`, `StructureFileRule` | 推荐目标根、目录规则和单文件例外，仍属只读方案 |
| `StructurePlan` | `plan_structure`；`StructureMapping`, `CopyTask`, `MergeSkip` | 完整旧→新文件映射、复制/复用及计划校验摘要 |
| `Plan` / `Move` | `plan_rename`, `plan_archive`, `plan_clean_duplicates`, `plan_retire_directory` | 受控变更集合；`RetirementProposal` 另列可隔离/阻断 |
| `PhotoReport` | `probe_photo`, `similar_photos` | 视觉相似候选与元数据，不等于精确相同文件组 |
| `Result`, `HistoryItem` | `execute_plan`, `execute_merge_plan`, `execute_structure_plan`, `history`, `undo_latest`, `recover_incomplete` | 执行/恢复结果与状态；不能假定全文件操作原子性 |

## 3. 三种身份必须区分

1. `PathIdentity`：目录树中的一个相对路径；相同内容可位于多个路径。
2. `FileObjectIdentity`：文件系统中实际普通文件对象（Windows 可查询文件 ID/卷）；硬链接可能共享一个对象。
3. `ContentIdentity`：**完整逐字节同内容**；不同文件对象可以共享同一内容身份。

照片 `VisualSimilarity` 是第四种、**弱得多**的关系，不能参加内容精确去重或双副本证明。

## 4. 建议树与映射决策模型

`SourceSnapshot → SuggestedDirectoryRules → UserDirectoryOverrides + FileOverrides → ResolvedMapping[] → PlanValidation → FrozenPlan`。

映射优先级：**用户显式单文件映射 > 用户显式目录映射 > 机器建议**。多个来源对应同一目标，仅在内容完整字节等价时允许复用。原始文件和空目录的归属都必须可列出；遇目标文件已存在、且内容不同的显式指定，拒绝计划而不擅自重命名。

建议的最终结构化记录（目标架构，不意味着 rc7 已存全部字段）：

```text
RootSession { root_id; root_path; scan_id; scan_state; errors[] }
Evidence { content_group_id; verified; file_object_id; relation_kind; reasons[] }
Proposal { proposal_id; source_scan_id; target_tree[]; rules[]; confidence_label; reasons[] }
Mapping { source_rel; target_rel; source_kind; action; bytes; evidence_ref; reason; user_override }
FrozenPlan { plan_id; root_id; source_digest; target_preconditions; mappings[]; operations[]; expected_bytes; warnings[] }
Execution { txn_id; plan_id; state; completed[]; incomplete[]; journal_ref; review_status }
```

**规划要求**：冻结 `root_id / source_snapshot_digest / target_preconditions / proposal_revision`，防止一个新扫描、用户改路径或另一个程序改目录后继续执行旧计划。`core.hpp` 现有字段及 `SnapshotEntry` 已承担部分保护，但上述持久化结构是完善目标。

## 5. 数据处理与性能策略

- 扫描构建一次 `Inventory`，同一版本供后续统计、推荐和规划使用；结果发生变化需要重新扫描或有证明的增量验证。
- 精确相同匹配顺序：**文件大小 → 采样/全文件指纹候选 → 最终字节比较**。不要为每个下游模块重复读全盘一次。
- 推荐依赖经验证的内容 ID 倒排关系，控制目录组合的候选规模；达到上限时展示“不完整”，不得伪称穷尽。
- 目录关系合并/相同检查分别保留“相对路径”与“内容多重集”的不同语义。
- 操作预览只用缓存映射和计划；真正执行之前须对实际文件系统再次校验。
- UI 只跨线程接收结果/进度和显示错误，后台任务不得直接修改 Win32 控件。

## 6. 文件系统适配与技术规范

Windows 侧使用宽字符文件路径和合法长路径策略。重名时考虑大小写不敏感文件系统、Windows 保留设备名、非法字符、ACL、只读、junction/symlink、硬链接、进程占用、意外磁盘断连。执行器不能根据路径字符串外观就证明文件对象身份或事务目标安全，必须按 Windows 文件系统真实状态复核。

## 7. 工程组织建议（渐进式；不强制此轮重构源码）

```text
app/win32/        UI shell, pages, dialogs, accessibility
app/workflows/    SmartWorkflow / ThemeWorkflow / PlanSession
core/inventory/   scanner, content groups, directory relations
core/planning/    recommendations, directory mapping, preview
core/operations/  merge, structure, rename, archive, retirement
core/security/    root guard, two-copy, journal, recovery
platform/windows/ WIC, file IDs, fsync/FlushFileBuffers, resources
qa/              test fixtures, smoke, performance and fault injection
```

从 `src/core.cpp` 中物理拆分模块需另建重构任务和回归验证，**先固定职责边界，后重构文件组织**，避免为追求模块美观破坏现有正确性。


## v2.1 基础层领域 API 与数据模型

- `plan_quarantine_selected(Inventory, Duplicates, selectedPaths)`：人工选取待隔离文件，计划阶段计算两个**未被本计划选中、物理文件对象不同**的保留者，生成精确来源快照；实际执行再次逐字节比较保留者和待隔离源。
- `DirectoryPairReport evaluate_directory_pair(...)`：不受推荐阈值限制的目录对多维报告，提供内容多重集交集、不同内容类型数、较小侧覆盖、Jaccard、相同路径内容、冲突、空目录数，明确不可用于自动删除的事实边界。
- `OverlapListing find_overlapping_dirs(..., max_results, cancel)`：任何有“可用内容”重合且互不包含的目录候选，保留总候选数、截断标志；搜索复杂度过大时显式报错而非虚报完整结果。
- 原有 `duplicate_dirs`/`plan_retire_directory`/`plan_merge_dirs`/`execute_plan`/`execute_merge_plan` 继续统一使用；无独立“智能文件操作执行器”。
- 基础 UI 只调用以上公开域 API，使用 `Plan`/`MergePlan` 预览并经现有事务框架执行。

候选搜索默认忽略零字节和常见系统缩略图作为“历史关联证据”；用户点选两目录时，`evaluate_directory_pair` 仍检查**全部文件和空目录**。两种口径不可混用。
