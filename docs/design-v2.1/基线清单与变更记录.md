## 本次与旧基线的实质区别

1. 从以 P0/P1/P2 分类为主转为**五个业务能力域**，同时保留 P0/P1/P2 的需求优先级。
2. 将“智能/主题/基础”确定为**三种呈现深度，共用一套领域核心**；任务级主题固定为七个。
3. 把原 17 类操作入口与 13 个数据视图统一归入五个基础分组与七个主题流程，不以菜单数量代表能力。
4. 分清**证据（精确相同/目录重合）**与**建议（是否融合/目标树）**，建议永远不能自动执行。
5. 将全根重组固化为阶段 A 非破坏性构建，阶段 B 旧目录隔离**单独授权**。
6. 两份副本的严格定义、硬链接排除、旧目录外保留者、隔离不释放空间等不变量集中定义。
7. 需求编号稳定并映射到 `core.hpp` API、测试入口、发布 Gate，补齐原文档零散的追溯。
8. 更新验证口径到 **rc7 源码、rc6 已有 Windows 实测证据、rc7 GUI 待复测**，不再沿用 rc5 未测试时的陈旧说法。

## 变更控制

- 每项新增、删除、改变含义的功能，先更新 SRS `FR/UX/BR/NFR` 对应 ID 与追溯 CSV。
- 若改动安全语义，必须更新 ADR 与 `06`，提交对应反例测试与 Windows 证据，才允许实施。
- 若只是界面视觉修订，不改变领域核心、不改安全阈值；同步更新 `07` 与 UI 自动化。
- 需求状态只允许 `目标 / 已编码 / 通过指定环境测试 / 发布验收通过 / 暂缓 / 排除`；不得混用。
- 重大业务策略变动升新主设计基线，如 v2.1 或 v3.0，不覆盖已冻结文件。
