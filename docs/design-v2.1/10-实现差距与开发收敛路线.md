# 10 当前 rc7 状态、实现差距与收敛路线

## 1. 版本对齐

- **需求与设计基线 v2.0**：本次统一产品体系、目标结构与验收条件。
- **实际源码 v1.0-rc7**：Win32 三层界面候选，核心代码仍继承 rc5/rc6。
- **Windows 最近的实测证据**：用户 rc6 Windows 编译、7/7 CTest、CLI smoke 通过；GUI smoke 在搜索筛选后失败。rc7 对 GUI 测试做了针对性修复，但 Windows 实际复测未提供。
- **正式 v1.0**：未发布；不能以文档更新代替源码和质量验收。

## 3. 开发顺序（不增新功能的质量收敛）

**M0 冻结设计与修复 GUI 自动验收**：引用本 v2.0 基线，给 rc7 GUI smoke 在真实 Windows 上复测。若失败要确认到底是测试脚本、控件事件、异步刷新还是内容错误，避免仅使断言“变绿”。交付原始日志和可复现测试。

**M1 三层导航精修**：将旧 13 数据视图收纳为五组，统一七个主题任务的主路径；完善智能六阶段的返回/拒绝/编辑/确认流程。不得改变文件操作核心。高 DPI、键盘操作、人类任务测试作为完成标准。

**M2 端到端安全回归**：在专用 NTFS/exFAT 测试目录验证结构生成、编辑映射、非覆盖复制、定向清退、失败恢复、文件占用、Unicode 和 junction。把“全部原文件在新结构中有对照”做成自动断言。

**M3 推荐与性能验证**：用真实混合目录与历史照片备份评估可解释性、错配率、复用率、目标结构的人工可接受性；记录数万文件与移动盘的耗时/内存，不提前指定无依据的 SLA。

**M4 发布候选裁决**：对所有 G0–G3 阻断项出具 PASS/FAIL/NOT RUN；必须解决所有已知可能导致数据丢失的问题。设备断电恢复没有充分证据时维持候选版或明确限制声明，不得宣传绝对安全。

## 4. 不应在收敛阶段增加的功能

跨硬盘索引、云服务、AI 人物识别、照片视频生成、自动永久删除、编辑器重写、多个并行完整结构方案、复杂拖拽结构编辑、通用资源嗅探。这些不是解决“当前界面混乱/安全未验收”的正确方向。

## 5. 文档与源码变更纪律

每一次变更必须记录：`需求 ID → 决策/模型 → 修改源文件 → 受影响风险 → 单元/集成/GUI 测试 → 结果证据 → 发布状态`。只有触及业务规则时才修改 SRS/ADR；纯 UI 风格改动不得未经批准改变双副本定义、内容比较标准或写入权限。将旧版 ZIP、历史发布说明作为存档，避免多个互相矛盾的“当前基线”。


## v2.1 更新的实现差距（以 rc8 为参照）

**本轮已编码（Linux 核心验证）**：人工精确重复文件隔离计划；任意指定目录对多指标只读评估；嵌套相似目录候选发现及显式截断；Win32 基础页上下文操作（人工多选、重复目录清退、两目录评估→融合预览）；CLI `pair`、`overlaps`、`quarantine-selected`；`tests/test_foundation.cpp`。

**待实现或深化**：保留/保护状态持久化、单文件完整基本复制与移动、用户可以编辑每一个合并冲突文件的目标、S2 按结构保留与 S3 独立合集完整实现、检索过滤与分页、大规模压力、Win32 界面人工可用性、真实 NTFS/USB 故障注入。用户关心的“基础能力扎实”要求这些缺口逐项完成后再正式发布。

**严禁误报**：先前 Windows rc6 7/7 与 smoke PASS 不能证明 rc8 代码通过 Windows 编译/GUI/安全；当前交付仍为源码候选版。
