# 09 功能整理、去重与现有源码对应（重点决策清单）

**目的**：清理的是**功能呈现和重复流程**，不是删掉有价值的底层算法。保留 7 类主题任务与 5 类基础证据组；停止向主界面堆积按钮和标签。

## 1. 旧界面功能入口处理表

`rc7 src/win_main.cpp` 的旧工具/命令 ID 仍然保留，作为兼容与内部路由。下面是**新产品归属和入口决策**：

| 旧操作入口（含兼容命令） | 统一归属 | 新用户可见入口 | 决策 |
|---|---|---|---|
| 选择根目录、扫描、停止 | A / 任务协调 | 智能首页顶栏/状态区，主题前置 | 保留，停止只对可取消任务有效 |
| 整理工作台 | 智能模式 | 默认入口 | 成为唯一综合入口，不与“建议结构”并列主导航 |
| 融合建议 | C1 | 智能第 2/3 阶段，T-01 | 合并为“发现的历史备份”卡片，详情可展开 |
| 融合目录 | D1 | T-01 | 并入主题任务，仍支持人工指定来源/目标 |
| 建议结构 | C2 | 智能建议/调整阶段 | 合并入综合流程，不单列一级按钮 |
| 编辑映射 | C3 | 智能调整阶段 | 上下文操作，仅有建议方案时可见 |
| 预览迁移 | C4 | 智能预览阶段 | 统一使用“查看完整影响”界面 |
| 拒绝建议 | C3 | 智能建议/调整阶段 | 保留清晰次级动作，不需要全局按钮 |
| 比较目录 / 目录关系 | B3 | T-06 / 基础“重复与关系” | 同一证据内核，不各自成为首页操作 |
| 批量重命名 | D3 | T-04 / 基础具体列表 | 集中为一个带预览的向导 |
| 整理归档 | D4 | T-07 和 T-03 的归档阶段 | 两主题复用同一个归档规划器 |
| 照片相似 | B5 | T-03 / 基础“照片与元数据” | 明示“需人工审核”，无删除按钮 |
| 隔离多余 | D5 | T-02 | 同用双副本执行器，不与旧目录清退混淆 |
| 清退旧目录 | D5 | T-05 / 智能复核页可选动作 | 另行授权，保留旧目录外两份的加严条件 |
| 执行计划 | D / E | 仅具体操作预览页 | 禁止全局常驻“执行计划”危险按钮 |
| 撤销操作 | E4 | 结果/历史页 | 显示可撤销范围和不可撤销的原因 |
| 导出 CSV | A3 / C4 | 各个明细页“导出报告” | 不在首页占据主要按钮 |

**唯一入口规则**：一个任务可以从三层到达，但展示最终执行时必须进入同一个计划会话。用户不能分别在“主题融合”和“基础融合”中看到不一致的结果或风险阈值。

## 2. 原 13 数据视图如何收纳

| 原始视图 | 新基础分组 | 在智能/主题中的用途 |
|---|---|---|
| 全部文件、文件夹大小 | ① 文件与空间 | 扫描概览、容量排行 |
| 重复文件、重复目录、目录关系、备份安全、目录比较 | ② 重复与目录关系 | 融合证据、清退依据、目录比较 |
| 相似照片 | ③ 照片与元数据 | 照片整理与候选人工审核 |
| 融合建议、建议目录结构、操作预览 | ④ 建议与计划 | 目标树、映射、影响预览 |
| 操作历史 | ⑤ 操作与恢复 | 执行结果、撤销、异常恢复 |
| 整理工作台 | **不属于基础明细视图** | 只作为智能模式首页/摘要，不再重复一个基础标签 |

因此基础模式实际保留 **12 种专业数据视图 + 1 个兼容内部工作台**，对外改成五个清晰分组。内部可以先保留 13 种 view ID 以降低改造风险，但不可继续将其全部暴露给普通用户。

## 3. API 与新业务域的代码对应

| 域 | 对应 rc7 `core.hpp` API | 处理原则 |
|---|---|---|
| A | `scan`, `human`, `extension_category`, `csv_quote` | 一次扫描作为同版方案的事实输入 |
| B | `deduplicate`, `duplicate_dirs`, `compare_dirs`, `directory_relations`, `similar_photos`, `backup_safety` | 精确证据与启发式分离 |
| C | `recommend_merges`, `suggest_structure`, `plan_merge_dirs`, `plan_structure`, `plan_clean_duplicates`, `plan_retire_directory` | 计划与推荐不写盘，输出完整动作/理由 |
| D | `plan_rename`, `plan_archive`, `execute_merge_plan`, `execute_structure_plan`, `execute_plan` | 统一受保护执行，不在 UI 内复制实现 |
| E | `undo_latest`, `recover_incomplete`, `history`, `SnapshotEntry`, `RetirementProposal` | 操作前后的底层安全约束、状态与追溯 |

`win_main.cpp` 中对 `JobResult/Task/UiLevel` 的管理是当前应用协调器的初步形态。未来可以拆为 `ScanSession/ProposalSession/PlanSession`，但必须先通过全量测试并保留已有 API 行为。

## 4. 合并、收敛、保留与不做

| 决策 | 项目 | 处理 |
|---|---|---|
| MERGE | 融合建议 + 手动融合 + 目录比较 | 一个主题“历史备份融合”，比较证据可展开 |
| MERGE | 建议结构 + 编辑目录/文件映射 + 迁移预览 | 一个“智能重组”流程，不分散成多个平级工具 |
| MERGE | 重复隔离 + 旧目录定向清退 | 共用验证器，但保留不同作用域和授权 |
| MERGE | 照片日期识别 + 照片归档 | 一个照片整理主题；相似候选不参与自动删除 |
| KEEP | 精确扫描/重复/目录相同/CSV/操作日志 | 作为基础能力或上下文详情完整保留 |
| KEEP | 规则归档和批量重命名 | 各有明确主题、操作预览与撤销 |
| HIDE | 十几个常驻命令按钮、13 个暴露的底层标签 | 不删除内部命令 ID，减少日常认知负担 |
| DEFER | 任意层级拖动目标树、多个方案对比、语义 AI 分类 | 需独立需求与验证，不能作为当前承诺 |
| EXCLUDE | 自动永久删除、全盘扫描、跨磁盘副本证明 | 不属于当前产品安全边界 |

## 5. 产品清理验收清单

- 打开软件无需看术语说明就知道“选目录→扫描”；首页无平铺技术按钮。
- 每项主题不要求用户跳到另一个主题才能完成当前目标。
- 原有 P0–P2 基础能力仍可由主题或基础分组找到。
- 无一个业务动作因从不同模式进入而多出或缺少安全检查。
- 计划预览只保留一套规范数据结构；执行后结果用同一历史审计方式呈现。
- 所有安全文案将“隔离”与“空间回收”、“内容精确相同”与“视觉相似”分开。


## v2.1 基础操作交互映射

| 新基础操作 | 复用的领域核心 | 当前 Win32 入口 | 仍未完成 |
|---|---|---|---|
| 手动精确重复文件清退 | `deduplicate` + `plan_quarantine_selected` + `execute_plan` | 基础→重复文件→多选→人工隔离 | 保留者永久保护标记、批量分组管理 UX 验收 |
| 完全重复目录手工管理 | `duplicate_dirs` + `plan_retire_directory` | 基础→重复目录→选择→安全清退 | 完整跨目录对应关系可视化 |

**原有智能与主题入口保留**，只是用基础能力公开 API 驱动，不允许为各层重新实现相似度或删除逻辑。
