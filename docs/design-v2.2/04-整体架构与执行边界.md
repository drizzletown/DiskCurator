# 04 总体架构、领域数据与执行边界

```text
Win32 原生界面：L3 智能整理 / L2 主题工具 / L1 基础工具
                   │ 用户扫描、策略选择、计划确认
任务调度：主扫描→完整哈希索引→内容识别→目录关系→建议/计划
                   │ Inventory, Duplicates, RetentionPolicy
共享领域核心：SHA256(index) + equal_bytes + 文件对象身份 + 目录/文件关系
                   │ Plan（固定策略及对应证据）
唯一事务执行器：计划检查→暂存→按选定模式复核→无覆盖提交→日志/恢复
                   │
受控本地 NTFS/exFAT 文件系统 + 独立用户缓存（不在资料根目录内）
```

## 核心数据对象

- `File`：相对路径、大小、mtime、内容组 ID、完整 SHA-256。
- `Inventory`：根目录、文件/目录树、错误列表及是否完整。
- `Duplicates`：按完整内容验证得到的重复组及失败项。
- `RetentionPolicy`：最小活动数量、独立对象开关、是否执行再次字节比较、是否允许零份。
- `Plan / Move`：冻结用户策略、保留者集合、扫描哈希、各保留者元数据快照以及待移动源对象快照。
- `MergePlan / StructurePlan`：独立的非破坏性复制和可编辑目录映射计划；原目录清退不属于自动执行的后续步骤。

## 事务边界

- 所有变更由原有 `execute_plan()`、`execute_merge_plan()`、`execute_structure_plan()` 进入事务代码；Win32 不直接操作用户资料。
- 副本策略为风险选择，不改变路径安全、无覆盖、防止隐藏 reparse 访问、日志恢复及快照完整性校验。
- 阶段 A 复制至目标，验证完成后保留原始文件；阶段 B 必须独立预览与确认，依据用户设定的清退策略执行。
- 正在执行的任务不允许中途直接关闭主窗口导致事务半途停滞；恢复失败时禁止继续危险写入。
- 单个活动内容可有多份副本，但同一磁盘上的多份并不形成磁盘容灾能力。

## 性能边界

当前只实现**全量哈希计算与本地索引保存**，不代表已实现 SQLite 增量重扫、并行 I/O 引擎或已达到百万文件 SLA。未来性能优化不得隐式改变用户配置的验证等级、哈希记录完整性或清退结果。
