# 00 产品目标与设计决策

## 目标

用户指定单根目录，对多年累积文件和多次备份进行统一盘点、完全重复识别、相似目录分析、主动建议融合/新目录树，并在用户修改与审批后完成安全整理。当前使用 Win32 SDK + C++17；非 Qt、非 MFC、无多硬盘索引或同步服务器。

## 业务能力与三层入口

- L1 基础工具：文件盘点/排序/查找；精确相同文件及人工隔离；完全相同目录及范围清退；相似目录发现；手工指定两目录比较与非覆盖融合；受控命名/归档/移动。
- L2 主题任务：历史备份融合、重复文件整理、相似照片核对、批量重命名、旧备份清退、目录对比、规则归档。
- L3 智能整理：扫描 → 发现 → 提案 → 编辑映射 → 预览/执行 → 复核与单独授权清退。

## 本次冻结的变更

| ADR | 决定 | 理由 |
|---|---|---|
| ADR-21 | 每次主扫描首先枚举目录并为所有可读取普通文件计算完整 SHA-256 | 让后续全部功能共享统一的哈希索引，而非重复按需计算 |
| ADR-22 | 哈希结果持久记录于用户应用缓存而非资料根目录 | 用户数据只读、索引可删除并重建 |
| ADR-23 | 以哈希按内容分桶，精确重复组仍需逐字节确认 | 对抗哈希碰撞与不一致文件，保证“完全相同”解释准确 |
| ADR-24 | 清退保留数、物理独立性与提交前复核方式为用户配置 | 不强加固定两份规则，用户明确承担选择后果 |
| ADR-25 | 推荐默认 2 份、不同文件对象、逐字节复核；0 份须单独授权 | 向普通用户提供安全默认，仍允许专家自定义 |
| ADR-26 | 快速模式使用本次全量扫描的 SHA-256 + 文件状态，须披露不可检测的变更 | 速度/可信性权衡由用户决定，不能假装与逐字节复核等价 |
| ADR-27 | 写入计划冻结策略快照；执行不读取可能已经改变的 UI 设置 | 保证用户预览和实际执行的约束一致 |
| ADR-28 | 阶段 A 非破坏性建立新结构；阶段 B 独立申请旧资料隔离 | 防止“融合成功 = 旧目录可直接删除”的误解 |

## 业务边界

- 可隔离 ≠ 可以永久删除；隔离区文件仍占空间。永久删除尚未实现，未来应单独定义确认/恢复边界。
- 保留两份普通文件 ≠ 分别保存在两块独立硬盘。即使启用不同文件对象检查，也只证明当前扫描根目录范围内文件对象不同。
- 内容相同 ≠ 照片视觉相似；dHash 不参与精确清退判定。
- 用户可降低安全策略，但不可通过无效路径、日志伪造或绕开事务执行器修改文件。
