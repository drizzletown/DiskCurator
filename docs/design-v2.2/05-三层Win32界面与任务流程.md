# 05 三层 Win32 原生界面与可配置策略交互

## L3 智能整理（默认）

选择根目录 → 完整扫描并记录 SHA256 → 查看发现 → 选择或修改建议目录树 → 预览映射 → 确认复制/核验新结构 → 复核 → 用户可选清退。扫描界面明确写“全量读取文件并计算 SHA-256”，展示计数/读取进度，不把元数据枚举完成写作完整扫描结束。

## L2 主题工具

历史备份融合、重复整理、照片整理、批量重命名、目录差异、旧目录清退、规则归档。每个任务只暴露其需要的输入和逐项预览，不在首页显示十几个按钮；涉及隔离则调用统一策略对话框。

## L1 基础工具

六组完整能力：盘点、精确重复文件人工管理、完全相同目录人工管理、相似目录发现、任意 A/B 相似度评估与融合、受控基本文件操作。精确重复文件页面显示 SHA256（完整值可通过 `dc_cli hashes` 和本机缓存导出）、大小、所在目录、组成员；人工选择具体隔离项后设置保留策略。

## 策略对话框

1. “至少保留几份活动文件？”——默认 2，可输入 0..32。
2. “是否必须是不同文件对象？”——默认勾选，关闭则硬链接路径也可作为不同活动路径计数。
3. “隔离前再完整核对字节？”——默认勾选，关闭改用当前全量 SHA256 + 文件状态快速模式；必须再次警告。
4. “允许零份活动副本？”——默认不勾选，仅 K=0 需要；必须再次确认，且下次不会自动授权。

用户确认以后进入**计划预览**，必须能查看：本次实际要隔离哪些文件、配置 K、实际保留哪些文件/路径、数据验证等级、冲突和 blocked 原因、隔离区不释放空间的提醒。执行后出具状态报告，不自动永久删除。

## 体验约束

深色侧栏和浅色主工作区保持简约，复杂选项仅在进入相关任务时出现；Win32 Common Controls/GDI 实现，不引入 Qt。列表使用虚拟化或按页处理以避免大量行卡顿；扫描与哈希计算必须在后台工作线程，并可取消。Windows 原生 GUI 的新配置项仍需实机测试，不可把 Linux 核心编译通过等同于 GUI 已验收。
