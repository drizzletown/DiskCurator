# 03 用户可配置的副本保留与验证策略

## 1. `RetentionPolicy`

| 设置 | 默认 | 可选 | 含义 |
|---|---:|---|---|
| 最少活动副本 `min_active_copies` | **2** | **0～32** | 执行后该内容在计划作用域内至少保留 K 个活动路径 |
| `distinct_file_objects` | 是 | 是/否 | 是：硬链接路径只能算一个文件对象；否：不同路径可以计数，风险较高 |
| `verify_bytes_before_change` | 是 | 是/否 | 是：隔离前与暂存后逐字节复核；否：信任本次 SHA256 + 大小/mtime 快速模式 |
| `allow_zero_active` | 否 | 只在 K=0 以独立确认启用 | 允许将同一组的所有活动文件转移到可撤销隔离区，风险很高 |

用户在 Win32 **人工隔离、自动整理重复文件、旧目录清退**任务启动时填写这些设置。正常设置保存至 `%LOCALAPPDATA%\DiskCurator\settings.ini` 并在下次使用时恢复；**零份授权不会持久记忆，每次都要重新勾选和风险确认**。CLI 提供 `--keep N`、`--count-hardlinks`、`--trust-scan-hash`、`--allow-zero`。

## 2. 计划和执行

1. 用户查看重复组或旧目录，选择操作目标和策略。
2. 计划引擎根据**最终结果**挑选允许保留的 K 个文件，若 `distinct_file_objects=true` 则检查它们不是相同物理文件对象。
3. 旧目录定向清退寻找的 K 个保留者，须位于**整个待清退目录范围之外**。
4. 若 `verify_bytes_before_change=true`，执行前及实际暂存后逐字节比较每一被隔离项和每一个保留者。
5. 若选择快速模式，要求本次完整 SHA256 索引以及被隔离文件与保留者的元数据符合计划快照；执行前不进行额外全量读取。**快速模式无力检测元数据被伪装的文件更改**。
6. K=0 仅在双重明确同意时允许，只移到软件隔离区，不永久删除；撤销仍需验证文件冲突。
7. `Plan` 冻结策略、保留者路径、必要的原始快照与哈希证据；用户在计划生成后修改设置不会修改已经确认的计划。

## 3. 决策例子

| 文件情况 | 配置 | 结果 |
|---|---|---|
| 4 份独立相同内容 | K=3, 独立=是 | 最多隔离 1 份 |
| 4 份独立相同内容 | K=1, 独立=是 | 最多隔离 3 份 |
| 仅 2 个硬链接路径、1 个真实独立副本 | K=2, 独立=是 | 最多只能隔离硬链接之一；不能隔离唯一真实独立副本 |
| 同上 | K=2, 独立=否 | 可把两个硬链接路径当 2 条活动路径，但并非两个独立文件对象 |
| 4 份独立相同内容 | K=0 且明确授权 | 可以全部隔离；活动树内可能不留此内容，隔离区成为唯一来源 |
| 1 份独有文件 | K=0 | 不能通过“重复文件”功能清退；需另行设计高风险普通文件操作 |

## 4. 术语与风险

- 文件内容是否相同、活动路径数量、物理文件对象数、跨硬盘备份数是四个不同概念，界面必须分别表达。
- 当前没有永久删除；所以“释放空间”不应出现在仅执行隔离的按钮承诺中。
- 快速模式和 K=0 都是**用户主动降低安全保证**；不能宣传为同样安全。
- 设置用户可调不等于允许程序忽略路径越界、目标覆盖、损坏事务日志、reparse point 或原始操作快照一致性。
